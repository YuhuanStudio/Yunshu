`GET /v1/models` 回傳這台伺服器可提供的模型。每個項目都是依磁碟上的檢查點檔案（設定檔、聊天模板、safetensors 標頭）推導出的模型卡，所以回答的是載入的權重實際能做什麼，而不是名稱讓人猜測的功能。同一個項目同時帶有多個生態系的欄位名稱，OpenAI、Anthropic、OpenRouter、vLLM 與 LM Studio 的用戶端都能找到自己要的欄位。Yunshu 自己的詳細資訊都放在單一的 `yunshu` 鍵底下。

<Endpoint method="GET" path="/v1/models" />
<Endpoint method="GET" path="/v1/models/{model_id}" />
<Endpoint method="POST" path="/v1/models/load" />
<Endpoint method="POST" path="/v1/models/unload/{model_id}" />

<Callout type="info">
只有在設定 `YUNSHU_AUTH_TOKEN` 時才會強制驗證。列出與查詢模型在沒有 token 時是開放的。載入與卸載屬於操作性路由：需要已設定的 token（或 `YUNSHU_AUTH_DISABLED=true`），見[載入與卸載](#載入與卸載)。
</Callout>

## 列出模型

`GET /v1/models` 沒有參數。回應是同時符合 OpenAI 與 Anthropic SDK 清單型別的 list 物件。

<Tabs items={["curl", "Python", "JavaScript"]}>
<Tab value="curl">

```bash
curl http://localhost:8000/v1/models -H "Authorization: Bearer sk-local"
```

</Tab>
<Tab value="Python">

```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8000/v1", api_key="sk-local")
for m in client.models.list():
    print(m.id)

import anthropic

a = anthropic.Anthropic(base_url="http://localhost:8000", api_key="sk-local")
for m in a.models.list():
    print(m.id, m.display_name, m.max_input_tokens)
```

</Tab>
<Tab value="JavaScript">

```ts
import OpenAI from "openai";

const client = new OpenAI({ baseURL: "http://localhost:8000/v1", apiKey: "sk-local" });
const models = await client.models.list();
for (const m of models.data) console.log(m.id);
```

</Tab>
</Tabs>

數值僅為示意，也省略了許多欄位；真實的項目帶有下表列出的所有欄位。多模型模式下，清單包含所有已註冊的模型，不論是否已載入；單模型模式下只有載入的那一個模型。沒有分頁：`has_more` 永遠是 `false`。

### 項目內容

| 方言 | 欄位 |
| --- | --- |
| OpenAI | `id`、`object`（`"model"`）、`created`、`owned_by`（`"yunshu"`） |
| Anthropic | `type`（`"model"`）、`display_name`、`created_at`、`max_input_tokens`、`max_tokens`、`capabilities` |
| OpenRouter | `name`、`canonical_slug`、`description`、`context_length`、`architecture`（`modality`、`input_modalities`、`output_modalities`、`tokenizer`）、`pricing`（全是 `"0"`）、`top_provider`、`supported_parameters`、`default_parameters` |
| vLLM | `root`、`parent`、`max_model_len`、`task`（`generate`、`embed`、`score`、`transcription`、`speech`、`image_generation`、`ocr`） |
| LM Studio | `arch`、`quantization`、`state`（`loaded` 或 `not-loaded`）、`max_context_length`、`publisher`、`compatibility_type`（`"mlx"`）、`model_type` |
| Yunshu | `yunshu`：完整的模型卡，說明如下 |

Anthropic 的 `capabilities` 物件包含 Anthropic SDK 模型要求的所有鍵（`batch`、`citations`、`code_execution`、`context_management`、`effort`、`image_input`、`pdf_input`、`structured_outputs`、`thinking`），其 `supported` 旗標來自模型卡。LM Studio 與 vLLM 用戶端使用的扁平布林值（`vision`、`trained_for_tool_use`、`tools`、`function_calling`、`reasoning`、`embedding`）也放在同一個物件內。

### `yunshu` 模型卡

| 欄位 | 意義 |
| --- | --- |
| `kind` | `chat`、`vlm`、`omni`、`embedding`、`reranker`、`classifier`、`decision`、`asr`、`tts`、`sts`、`image`、`ocr` 或 `video`。 |
| `family`、`architecture`、`parameters` | 從檢查點讀出的模型家族、架構類別與參數量。 |
| `quantization` | 位元寬度、群組大小與模式；混合精度的檢查點還有逐層分組。 |
| `input_modalities`、`output_modalities` | `text`、`image`、`video`、`audio`、`embedding`、`score`、`decision` 的子集。 |
| `context` | `length` 與其推導方式。`max_output_tokens` 是對外宣告的輸出上限。 |
| `reasoning` | 模型是否有思考模式、切換開關、預設狀態、強度等級與別名。 |
| `tools`、`structured_output`、`logprobs` | 工具呼叫的支援與模式、支援的約束類型、最大的 `top_logprobs`。 |
| `embeddings` | Embedding 模型的向量維度、池化方式與是否正規化。 |
| `audio`、`image` | 語音與圖像模型的模態專屬細節。 |
| `speculative` | 模型具備的推測解碼方法（例如 `mtp`）以及是否無損。 |
| `prefix_cache` | 前綴快取是否服務此模型，以及類型。 |
| `state`、`memory` | 已載入、載入中、固定、錯誤；權重位元組數與預估記憶體。 |
| `api` | 哪些路由與線上格式可服務此模型。 |
| `supported_parameters` | chat 路由對此模型接受的請求欄位。 |
| `generation_defaults` | 來自檢查點 `generation_config.json` 的取樣預設值。 |
| `contract` | 能力契約，見下文。 |
| `capability_tags` | 扁平標籤，例如 `chat`、`tools`、`vision`、`thinking`。 |
| `server_tools` | 文字類模型專用：閘道執行的工具（網頁搜尋提供者、MCP 連接器）設定了哪些。 |

匿名呼叫者看不到檔案系統路徑，也看不到常駐狀態。出示已設定的 `YUNSHU_AUTH_TOKEN` 的請求，每個項目還會有 `loaded`、`size_gb`、`size_bytes` 與 `stats`，以及 `yunshu.path` 和帶有模型管理器計數器的頂層 `registry` 物件。沒有設定 token 時，所有人都是匿名。

## 查詢單一模型

`GET /v1/models/{model_id}` 以相同結構回傳單一項目。id 可以含斜線（`mlx-community/Qwen3.5-0.8B-MLX-bf16`），解析方式與推論相同：精確 id、別名、不分大小寫比對。未知的 id 回應 `404`：

```json
{
  "error": {
    "message": "Model 'nope' not found",
    "type": "invalid_request_error",
    "param": null,
    "code": "model_not_found"
  }
}
```

即使在生成路由接受任何名稱的單模型模式下，這個路由對伺服器沒有列出的 id 仍會回應 `404`。

## 能力契約

每張模型卡都有 `yunshu.contract` 物件，每個生成路由也都強制執行同一個物件，所以清單能精確告訴你請求可以用到什麼。

| 鍵 | 內容 |
| --- | --- |
| `tools` | `supported`；`mode`（聊天模板能轉換 tools 時為 `template`，由 Yunshu 注入工具提示時為 `prompt`）；`parallel`；接受的 `tool_choice` 值。 |
| `structured_output` | `json_object`；`json_schema` 與其引擎（`in-house`，超出內建子集的 schema 另有 `llguidance`）；`regex`；`choice`；`grammar`（Lark 語法，透過 `llguidance`）。 |
| `logprobs`、`reasoning` | 支援與否、最大的 `top_logprobs`、強度等級。 |
| `media` | 文字以外的輸入與輸出模態。 |
| `speculative` | `mode`（`mtp`、`dflash2` 或 `none`）與 `lossless`。 |
| `cache_tiers` | `ram`，啟用 SSD 層時還有 `ssd`。 |
| `context` | 視窗長度與最大輸出 token 數。 |
| `unsupported_fields` | 永遠是 `"400"`。 |

請求若用到契約排除的功能，會回應 `400` 並指出欄位，格式採用該方言的錯誤格式：

- 對不接受該輸入的模型送出 `image`、`audio` 或 `video` 內容區塊；
- 對不生成文字的模型（embedding、reranker、語音、圖像模型）使用 `tools`、`tool_choice`、`response_format`、`grammar`、`guided_*` 欄位或 `logprobs`。

對沒有推理模式的模型使用 `reasoning_effort` 與 `thinking_budget` 會被刻意接受但沒有作用，因為程式設計 agent 每個請求都會帶推理強度。設定檔無法讀取的檢查點沒有契約，也不受限制。

## 載入與卸載

<Callout type="warn">
這些路由會改變記憶體中的內容，因此需要驗證：沒有設定 `YUNSHU_AUTH_TOKEN`（且 `YUNSHU_AUTH_DISABLED` 不是 true）時會回應 `401`，訊息為 `No authentication configured. Set YUNSHU_AUTH_TOKEN or YUNSHU_AUTH_DISABLED=true.` 設定 token 後，與其他路由一樣送出它即可。
</Callout>

### 載入模型

`POST /v1/models/load` 載入模型並啟動它的引擎。

| 參數 | 型別 | 必填 | 說明 | 狀態 |
| --- | --- | --- | --- | --- |
| `model` | string | 是 | 在模型管理器中註冊的模型 id。接受 `model_id` 作為別名；兩者都送時以 `model` 為準。 | 支援 |
| `pin` | boolean | 否 | 預設 `false`。 | 接受但忽略 |

```bash
curl -X POST http://localhost:8000/v1/models/load \
  -H "Authorization: Bearer $YUNSHU_AUTH_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"model": "mlx-community/Qwen3.5-0.8B-MLX-bf16"}'
```

```json
{ "status": "loaded", "model": "mlx-community/Qwen3.5-0.8B-MLX-bf16" }
```

多模型模式下，模型必須已註冊（位於 `YUNSHU_MODELS_DIR` 下），否則回應 `404`。沒有模型管理器時，這個路由會把指定的路徑載入唯一的引擎；批次引擎則會拒絕（`400`）。

### 卸載模型

`POST /v1/models/unload/{model_id}` 釋放模型佔用的記憶體。僅限多模型模式（其他情況回應 `400`）。id 的解析方式（別名與大小寫）與推論相同。

```bash
curl -X POST http://localhost:8000/v1/models/unload/mlx-community/Qwen3.5-0.8B-MLX-bf16 \
  -H "Authorization: Bearer $YUNSHU_AUTH_TOKEN"
```

```json
{ "status": "unloaded", "model": "mlx-community/Qwen3.5-0.8B-MLX-bf16" }
```

仍有請求在處理中的模型不會被卸載（`409`），因此執行中的生成不會被硬生生中斷。

### 錯誤

| 狀態碼 | 時機 |
| --- | --- |
| 400 | `model` 為空；載入失敗且有特定原因（訊息會說明）；在批次引擎上做單一引擎載入；在多模型模式之外卸載。 |
| 401 | 沒有設定 token，或 token 缺少或不正確。 |
| 404 | 未知的模型（`GET`、卸載），或尚未註冊的模型（載入）。 |
| 409 | 同一個模型正在載入或卸載中；卸載時仍有作用中的請求，或模型在卸載期間變成使用中。 |
| 500 | 載入因未預期的原因失敗（`Model loading failed`）。 |
| 503 | 引擎尚未初始化。 |
