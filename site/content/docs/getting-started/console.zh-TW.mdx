主控台是由 Yunshu 閘道本身提供的小型網頁應用，與 API 使用相同的位址與連接埠。它是單一執行中引擎的檢視介面：顯示即時狀態、讓你載入與卸載模型、列出請求，並提供 Playground 來送出測試請求。它不會啟動或停止 Yunshu 行程，也不是聊天產品。

<Callout type="info">
主控台介面以繁體中文撰寫。下方列出的標籤就是你在介面上會看到的名稱。
</Callout>

## 開啟主控台

照常啟動伺服器，然後在瀏覽器中開啟伺服器位址的 `/console/`。使用預設主機與連接埠時，就是 `127.0.0.1` 的 8000 埠、路徑 `/console/`。

靜態頁面是公開的，讓你可以在瀏覽器中輸入 token。主控台發出的每個 API 呼叫仍遵循一般的驗證規則：伺服器設定了 `YUNSHU_AUTH_TOKEN` 時，請在主控台（設定頁）輸入該 token。token 只保存在頁面記憶體中，重新整理頁面或變更伺服器位址時會清除；不會存入瀏覽器、網址、匯出檔或程式碼片段。

如果 `/console/` 回應 404 並顯示「Yunshu Console is not built」，表示已安裝的套件不含主控台建置產物，API 不受影響。從原始碼 checkout 建置主控台需要 Node.js 22.18 或更新版本與 pnpm：

```bash
cd frontend
pnpm install --frozen-lockfile
pnpm build
```

建置結果會寫入 `python/yunshu_gateway/console_static`，由閘道提供服務。

## 頁面

| 頁面（主控台中的標籤） | 功能 |
|---|---|
| 總覽（`引擎總覽`） | 頁面可見時每三秒取樣一次引擎狀態：吞吐量、請求數、記憶體與快取數據。可暫停、恢復取樣或手動重新整理。 |
| 模型（`模型庫`） | 列出模型與其狀態；載入、卸載與預熱模型，並管理閒置保留時間。 |
| 請求與效能（`請求與效能`） | 即時與近期結束的請求、篩選、匯出 CSV、請求詳情與逐一請求取消。 |
| API 接入（`API 接入`） | 針對你的伺服器產生連線範例，以及從其 OpenAPI 文件讀取的路由目錄。 |
| 診斷（`引擎診斷`） | 伺服器診斷端點的原始資料（系統、引擎、請求、KV 快取、SSD 快取、推測式解碼、各模型數據、記憶體）。 |
| Playground（`推理測試`） | 帶有生成設定的串流聊天請求。 |
| 設定（`設定`） | 伺服器位址、存取 token、主題與各模型的閒置保留時間。 |

### 總覽與請求

主控台每三秒讀取一次 `GET /v1/yunshu/status`。更新失敗時，會保留最後一筆資料並標示為過期或已斷線。歷史資料只存在頁面中（最多 1,200 筆觀測），不會被儲存；重新整理頁面或偵測到伺服器重新啟動時會清除。伺服器未回報的數值會顯示為無資料，而不是 0。

請求清單來自狀態端點回報的內容，因此它是觀測紀錄，而不是完整歷史。伺服器只提供最近一筆已結束的請求，所以在兩次取樣之間結束的請求可能缺漏。進行中請求的詳情會輪詢 `GET /v1/requests/{request_id}`，取消則送出 `DELETE /v1/requests/{request_id}`。已結束的列標示為「已結束」，而非「成功」。

### 模型

模型操作使用 `POST /v1/models/load`、`POST /v1/models/unload/{model_id}` 與 `POST /v1/yunshu/warmup`，模型詳情來自 `GET /v1/models/{model_id}`。卸載前會要求確認。在單一模型模式下，模型一律保留，無法從主控台卸載；有請求正在執行時，伺服器也可能拒絕卸載。從 Hugging Face 匯入 MLX 模型、以新名稱複製模型，以及刪除模型，使用相容 Ollama 的路由 `POST /api/pull`、`POST /api/copy` 與 `DELETE /api/delete`；刪除時必須輸入完整的模型 id。匯入時只會顯示等待伺服器，因為這些路由沒有進度或取消串流。各模型的閒置保留使用 warmup 路由的 `keep_alive` 值。

模型的載入、卸載與刪除屬於操作性呼叫：設定了 `YUNSHU_AUTH_TOKEN` 時需要伺服器的 token，沒有設定 token 時則會被拒絕。請見[模型 API](/docs/api/models)。

### Playground

Playground 送出 OpenAI 風格的串流聊天請求，並顯示內容與推理輸出。你可以設定思考模式（自動、開、關）、輸出格式（文字或 JSON）、temperature 與其他生成設定。對於視覺語言模型，可附加最大 8 MB 的 PNG、JPEG 或 WebP 圖片；圖片以 OpenAI 的 image part 送出，且不會被儲存。停止或離開頁面都會中止串流。因長度上限被截斷的回覆會明確標示，未完成或失敗的助理訊息不會在後續輪次中被當作上下文送回。語音、影片生成與工具執行不會在 Playground 中對應成聊天；這些功能請直接使用 API。

### 診斷

診斷頁讀取伺服器需驗證的診斷端點。若你的伺服器停用或沒有某項診斷，頁面會如實標示。API 探索是從你所連線伺服器的 `/openapi.json` 讀取，而不是使用內建的路由清單。

## 連線設定

預設情況下，主控台與提供它的來源通訊。你可以在設定頁讓它指向另一台 Yunshu 伺服器；該伺服器必須透過 CORS 設定（`YUNSHU_CORS_ORIGINS`）允許主控台的來源。只有伺服器位址與主題會存入瀏覽器的 local storage。驗證失敗時，輪詢會暫停，直到你重試或變更連線。

## 主控台不做的事

- 沒有 API 金鑰管理，也沒有用量配額。存取控制就是[設定](/docs/guides/configuration)中所述的單一 `YUNSHU_AUTH_TOKEN`。
- 不會變更伺服器的啟動設定，也不會停用驗證。
- 不保存持久的請求歷史。
