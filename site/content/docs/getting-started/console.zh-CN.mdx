---
title: 控制台
description: Yunshu 服务器内置的网页控制台，用来观察引擎状态、管理模型、查看请求并试用 API。
---

控制台是由 Yunshu 网关本身提供的小型网页应用，与 API 使用相同的地址和端口。它是单个运行中引擎的查看界面：显示实时状态、让你加载和卸载模型、列出请求，并提供 Playground 来发送测试请求。它不会启动或停止 Yunshu 进程，也不是聊天产品。

<Callout type="info">
控制台界面以繁体中文编写。下方列出的标签就是你在界面上会看到的名称。
</Callout>

## 打开控制台

照常启动服务器，然后在浏览器中打开服务器地址的 `/console/`。使用默认主机和端口时，就是 `127.0.0.1` 的 8000 端口、路径 `/console/`。

静态页面是公开的，这样你可以在浏览器中输入 token。控制台发出的每个 API 调用仍遵循常规的认证规则：服务器设置了 `YUNSHU_AUTH_TOKEN` 时，请在控制台（设置页）输入该 token。token 只保存在页面内存中，刷新页面或更改服务器地址时会清除；不会存入浏览器、网址、导出文件或代码片段。

如果 `/console/` 返回 404 并显示 “Yunshu Console is not built”，说明已安装的软件包不含控制台构建产物，API 不受影响。从源码 checkout 构建控制台需要 Node.js 22.18 或更新版本与 pnpm：

```bash
cd frontend
pnpm install --frozen-lockfile
pnpm build
```

构建结果会写入 `python/yunshu_gateway/console_static`，由网关提供服务。

## 页面

| 页面（控制台中的标签） | 功能 |
|---|---|
| 总览（`引擎總覽`） | 页面可见时每三秒采样一次引擎状态：吞吐量、请求数、内存与缓存数据。可暂停、恢复采样或手动刷新。 |
| 模型（`模型庫`） | 列出模型及其状态；加载、卸载和预热模型，并管理空闲保留时间。 |
| 请求与性能（`請求與效能`） | 实时与近期结束的请求、筛选、导出 CSV、请求详情与逐个请求取消。 |
| API 接入（`API 接入`） | 针对你的服务器生成连接示例，以及从其 OpenAPI 文档读取的路由目录。 |
| 诊断（`引擎診斷`） | 服务器诊断端点的原始数据（系统、引擎、请求、KV 缓存、SSD 缓存、推测式解码、各模型数据、内存）。 |
| Playground（`推理測試`） | 带有生成设置的流式聊天请求。 |
| 设置（`設定`） | 服务器地址、访问 token、主题和各模型的空闲保留时间。 |

### 总览与请求

控制台每三秒读取一次 `GET /v1/yunshu/status`。刷新失败时，会保留最后一次的数据并标示为过期或已断开。历史数据只存在页面中（最多 1,200 条观测），不会被保存；刷新页面或检测到服务器重启时会清除。服务器未报告的数值会显示为无数据，而不是 0。

请求列表来自状态端点报告的内容，因此它是观测记录，而不是完整历史。服务器只提供最近一条已结束的请求，所以在两次采样之间结束的请求可能缺失。进行中请求的详情会轮询 `GET /v1/requests/{request_id}`，取消则发送 `DELETE /v1/requests/{request_id}`。已结束的行标示为“已结束”，而非“成功”。

### 模型

模型操作使用 `POST /v1/models/load`、`POST /v1/models/unload/{model_id}` 和 `POST /v1/yunshu/warmup`，模型详情来自 `GET /v1/models/{model_id}`。卸载前会要求确认。在单模型模式下，模型始终保留，无法从控制台卸载；有请求正在运行时，服务器也可能拒绝卸载。从 Hugging Face 导入 MLX 模型、以新名称复制模型，以及删除模型，使用兼容 Ollama 的路由 `POST /api/pull`、`POST /api/copy` 和 `DELETE /api/delete`；删除时必须输入完整的模型 id。导入时只会显示等待服务器，因为这些路由没有进度或取消流。各模型的空闲保留使用 warmup 路由的 `keep_alive` 值。

模型的加载、卸载和删除属于操作性调用：设置了 `YUNSHU_AUTH_TOKEN` 时需要服务器的 token，没有设置 token 时则会被拒绝。参见[模型 API](/docs/api/models)。

### Playground

Playground 发送 OpenAI 风格的流式聊天请求，并显示内容与推理输出。你可以设置思考模式（自动、开、关）、输出格式（文本或 JSON）、temperature 和其他生成设置。对于视觉语言模型，可附加最大 8 MB 的 PNG、JPEG 或 WebP 图片；图片以 OpenAI 的 image part 发送，且不会被保存。停止或离开页面都会中止流。因长度上限被截断的回复会明确标示，未完成或失败的助手消息不会在后续轮次中被当作上下文发回。语音、视频生成和工具执行不会在 Playground 中映射为聊天；这些功能请直接使用 API。

### 诊断

诊断页读取服务器需认证的诊断端点。若你的服务器禁用或没有某项诊断，页面会如实标示。API 发现是从你所连接服务器的 `/openapi.json` 读取，而不是使用内置的路由列表。

## 连接设置

默认情况下，控制台与提供它的来源通信。你可以在设置页让它指向另一台 Yunshu 服务器；该服务器必须通过 CORS 配置（`YUNSHU_CORS_ORIGINS`）允许控制台的来源。只有服务器地址和主题会存入浏览器的 local storage。认证失败时，轮询会暂停，直到你重试或更改连接。

## 控制台不做的事

- 没有 API 密钥管理，也没有用量配额。访问控制就是[配置](/docs/guides/configuration)中所述的单个 `YUNSHU_AUTH_TOKEN`。
- 不会更改服务器的启动配置，也不会禁用认证。
- 不保存持久的请求历史。
