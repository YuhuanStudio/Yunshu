title: 服务
description: 通过 yunshu service 管理的用户级 launchd 代理，让 Yunshu 在登录时于后台运行。
---

`yunshu service` 在 macOS 上管理用户级的 launchd 代理（agent）。该 agent 会在你登录时启动 Yunshu，当进程崩溃时重新启动（正常停止则不会），并把输出写入会自动轮转的日志文件。它以你的身份运行，不需要 root 权限，也不会改动下列两个路径以外的任何位置。

| 项目 | 位置 |
|---|---|
| launchd agent | `~/Library/LaunchAgents/com.yuhuanstudio.yunshu.plist` |
| 日志 | `~/Library/Logs/Yunshu/yunshu.log` |

该命令仅限 macOS。无论通过 uv、pip 还是 Homebrew 安装，用法都相同；Homebrew formula 没有另外定义 service。

## 安装

可以先检查模型，再安装：

```bash
yunshu doctor -m mlx-community/Qwen3.5-9B-MLX-4bit
yunshu service install -m mlx-community/Qwen3.5-9B-MLX-4bit
```

`install` 接受决定要服务什么、在哪里服务的选项：

| 选项 | 说明 |
|---|---|
| `--model`、`-m` | 模型文件夹或 Hugging Face repo id。已存在的路径会以绝对路径保存。 |
| `--models-dir`、`-d` | 服务此目录中的所有模型（多模型模式）。 |
| `--host` | 绑定的主机。默认 `127.0.0.1`。 |
| `--port`、`-p` | 绑定的端口。默认 `8000`。 |
| `--config`、`-c` | 服务每次启动时都会读取的 TOML 配置文件，文件必须存在。 |
| `--set KEY=VALUE` | 在安装时固定的设置，可重复使用。 |
| `--dry-run` | 以 property list 格式打印 launchd agent，不做任何更改。 |
| `--no-start` | 写入 agent 但不立即启动。 |
| `--force` | 替换已安装的 agent。 |

你必须指明要服务什么：传入 `--model` 或 `--models-dir`，或已设置 `YUNSHU_MODEL`。`install` 会拒绝未通过 `yunshu doctor -m` 同一套模型检查的模型（例如路径不存在或下载不完整）。若已安装 agent，除非加上 `--force`，否则 `install` 会报错停止。

agent 使用执行 `install` 的那个安装环境所用的 Python 来运行 `python -m yunshu_cli serve ...`。在同一个环境升级 Yunshu 之后，请执行 `yunshu service restart`。若换到不同的环境，请重新执行 `yunshu service install --force ...`。

```bash
yunshu service install -m mlx-community/Qwen3.5-9B-MLX-4bit --dry-run   # 先查看
```

### 服务使用的设置

你在 shell 中 `export` 的设置不会被复制到服务。请把它们写进以 `--config` 传入的配置文件，或用 `--set` 固定。环境变量 `HF_HOME`、`HF_HUB_CACHE`、`HF_ENDPOINT` 和 `HF_HUB_OFFLINE` 是例外：它们会被复制，让服务找到同一个 Hugging Face 缓存。未指定 `--config` 时，服务仍会读取 `yunshu config set` 写入的用户级文件 `~/.yunshu/config.toml`。服务的 `PATH` 固定为 `/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin`。

配置文件是扁平的 `KEY = value` TOML：

```toml
# ~/.yunshu/yunshu.toml
YUNSHU_AUTH_TOKEN = "change-me"
YUNSHU_LOG_KEEP = 14
```

```bash
yunshu service install -m mlx-community/Qwen3.5-9B-MLX-4bit -c ~/.yunshu/yunshu.toml
```

若绑定非本机的 `--host`，请同时设置认证 token。所有设置参见[配置](/docs/guides/configuration)。

## 日常命令

```bash
yunshu service status        # 已安装 / 运行中（pid）/ 是否健康，以及路径
yunshu service logs -n 100   # 最后 100 行（默认 50）
yunshu service logs -f       # 持续跟踪日志
yunshu service restart       # 例如编辑配置文件之后
yunshu service stop          # 停止，直到下次登录或执行 `service start`
yunshu service start
yunshu service uninstall     # 停止并移除 agent；模型与日志会保留
```

| 命令 | 行为 |
|---|---|
| `status` | 报告 agent 是否已安装与加载、pid 与上次退出码、安装时使用的 URL，以及 `GET /health` 是否有响应。`--json` 返回相同的信息。 |
| `logs` | 显示最后 `--lines`/`-n` 行。`--follow`/`-f` 持续输出，且不能与 `--json` 同时使用。尚无日志文件时会失败。 |
| `start` | 启动已安装的 agent。尚未安装时会失败。 |
| `stop` | 卸载 agent。直到下次登录或执行 `start` 之前都会保持停止。 |
| `restart` | 重新启动运行中的 agent。服务未运行时会失败，此时请改用 `start`。 |
| `uninstall` | 停止 agent 并删除 plist。模型与日志会保留。 |

agent 被配置为崩溃后重新启动、正常退出则不重启，且 launchd 两次重启之间至少间隔 10 秒。若模型无法加载，服务器仍会保持运行，`GET /health/ready` 会返回 503 并附上原因，而不是让进程反复退出重启。

## 日志轮转

服务在运行期间会自行轮转日志。轮转按大小与时间进行；被轮转的文件是已去除 token 与 API 密钥的 gzip 压缩文件。下列设置控制轮转：

| 设置 | 默认值 | 说明 |
|---|---|---|
| `YUNSHU_LOG_MAX_MB` | 50 | 达到此大小（MiB）时轮转。0 表示关闭按大小轮转。 |
| `YUNSHU_LOG_ROTATE_HOURS` | 24 | 经过此小时数也会轮转。0 表示关闭按时间轮转。 |
| `YUNSHU_LOG_KEEP` | 7 | 保留的已轮转文件数量。 |
| `YUNSHU_LOG_RETENTION_DAYS` | 14 | 删除超过此天数的已轮转文件。0 表示保留，直到被 `YUNSHU_LOG_KEEP` 清理。 |

`yunshu service rotate-logs` 会立即轮转日志，适合在服务已停止时使用。

## 完整卸载

```bash
yunshu service uninstall
uv tool uninstall yunshu               # 或：brew uninstall yunshu、pip uninstall yunshu
rm -rf ~/Library/Logs/Yunshu
rm -rf ~/.yunshu                       # 下载的模型与配置：删除前请确认
```

前缀缓存的 SSD 层位于 `~/.yunshu/cache/apc`，除非 `YUNSHU_VLM_APC_DISK_DIR` 指向其他位置；若你设置过，也请一并删除该目录。
