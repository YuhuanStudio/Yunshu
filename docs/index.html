Yunshu

Production-grade MLX-based LLM inference platform for Apple Silicon clusters. Drop-in replacement for oMLX with 5 modalities, 5 protocols, and 4-tier KV caching.

5 Modalities 5 Protocols 4-Tier KV Cache Apple Silicon Native

Multi-Modal Inference

  • LLM — Chat completions, text completions, continuous batching via mlx-lm BatchGenerator
  • VLM — Vision-language models with self-contained MLX ViT + spatial merge pipeline
  • TTS — Text-to-speech via mlx-audio backends (Kokoro-82M, etc.)
  • ASR — Automatic speech recognition via Whisper MLX ports
  • Image — Diffusion model image generation (Stable Diffusion XL, FLUX.1-schnell)

Protocol Support

  • OpenAI — Full API compatibility (chat, completions, embeddings, audio, images)
  • Anthropic — Messages API compatibility layer
  • MCP — Model Context Protocol with tool registration
  • Realtime — WebSocket bidirectional audio/text streaming with ASR + TTS
  • Admin — Model management, health, metrics, tenant management, KV stats

4-Tier KV Cache Hierarchy

  • Hot — GPU-resident paged attention (Metal kernels)
  • Warm — CPU-resident quantized cache with KIVI compression
  • Cool — Disk-backed SSD cache for prefix sharing
  • Cold — Distributed cache across compute mesh nodes

Installation

Prerequisites

  • macOS with Apple Silicon (M1/M2/M3/M4)
  • Python 3.12+ (3.13+ recommended)
  • uv — Python package manager (curl -LsSf https://astral.sh/uv/install.sh | sh)
  • just — command runner (brew install just)
  • pnpm — for WebUI development (optional)

Quick Setup

# Clone the repository
git clone https://github.com/YuhuanStudio/yunshu.git
cd yunshu

# Option A: Automated setup (checks all prerequisites)
bash scripts/dev_setup.sh

# Option B: Manual setup
just setup              # install Python deps + WebUI deps

# Verify installation
just test-unit          # run unit tests

One-Line Install

git clone https://github.com/YuhuanStudio/yunshu.git && cd yunshu && bash scripts/dev_setup.sh

Quick Start

1. Start the server

# Single-model mode (load a specific model)
just dev

# Or specify a model path
YUNSHU_MODEL=./models/Qwen3.5-9B-MLX-4bit just dev

# Multi-model mode (auto-discovers models in ./models/)
just dev-multi

2. Make your first request (curl)

curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "Qwen3.5-9B-MLX-4bit",
    "messages": [{"role": "user", "content": "Hello!"}],
    "stream": true
  }'

3. OpenAI Python SDK

from openai import OpenAI

client = OpenAI(base_url="http://localhost:8000/v1", api_key="any")

response = client.chat.completions.create(
    model="Qwen3.5-9B-MLX-4bit",
    messages=[{"role": "user", "content": "Explain quantum computing"}],
    stream=True,
)
for chunk in response:
    if chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="")

4. Anthropic Python SDK

import anthropic

# Point to Yunshu's Anthropic-compatible endpoint
client = anthropic.Anthropic(
    base_url="http://localhost:8000/v1",
    api_key="any",
)

message = client.messages.create(
    model="Qwen3.5-9B-MLX-4bit",
    max_tokens=256,
    messages=[{"role": "user", "content": "Hello!"}],
)
print(message.content[0].text)

5. Load / Unload Models via API

# Load a model
curl -X POST http://localhost:8000/api/v1/admin/models/load \
  -H "Content-Type: application/json" \
  -d '{"model_id": "my-model", "model_path": "./models/my-model"}'

# Unload
curl -X POST http://localhost:8000/api/v1/admin/models/unload \
  -H "Content-Type: application/json" \
  -d '{"model_id": "my-model"}'

6. Python SDK

from yunshu_sdk import YunshuClient

client = YunshuClient("http://localhost:8000")

# List models
models = client.models.list()

# Chat completion
response = client.chat.completions.create(
    model=models[0].id,
    messages=[{"role": "user", "content": "Hello!"}],
    max_tokens=128,
)
print(response.choices[0].message.content)

Configuration Reference

All configuration is via environment variables.

Variable Default Description
YUNSHU_MODEL — Path to a single model to load on startup.
YUNSHU_MULTI_MODEL — Set to 1 to enable multi-model mode with auto-discovery.
YUNSHU_MODELS_DIR ./models Directory to scan for models (multi-model mode).
YUNSHU_PORT 8000 Server port.
YUNSHU_HOST 0.0.0.0 Server bind address.
YUNSHU_MAX_MEMORY_GB 80% of UMA Max GPU memory (GB) for the ProcessMemoryEnforcer.
YUNSHU_AUTH_TOKEN — Bearer token for API authentication. If unset, no auth required.
YUNSHU_AUTH_DISABLED — Set to true to explicitly disable auth (shows warning).
YUNSHU_CORS_ORIGINS * Comma-separated CORS origins. Restrict for production.
YUNSHU_MODEL_TTL_SECONDS — Time-to-live (seconds) for idle models before eviction.
YUNSHU_MEMORY_POLL_INTERVAL 2.0 Seconds between memory enforcer polls.
YUNSHU_RATE_LIMIT_RPM 0 Requests per minute per client (0 = unlimited).
YUNSHU_LOG_LEVEL INFO Logging level (DEBUG, INFO, WARNING, ERROR).
YUNSHU_WEBUI_ENABLED 0 Enable Next.js dashboard at /dashboard.

Architecture Overview

Yunshu is a 5-layer stack designed for Apple Silicon clusters. See the Architecture page for detailed diagrams and explanations.

L0 Client Swift app / CLI / SDK
L1 Gateway FastAPI — OpenAI / Anthropic / MCP / Realtime / Admin
L2 Control Plane Scheduling, RBAC, management API
L3 Compute Mesh mx.distributed — JACCL / Ring / MPI
L4 Engine 5-modality inference, continuous batching
L5 KV Hierarchy Hot / Warm / Cool / Cold 4-tier KV storage

Performance

Yunshu is optimized for Apple Silicon with Metal kernels for PagedAttention, Flash Attention 3, and KIVI quantization. See the Benchmarks page for detailed results.

  • Continuous batching via mlx-lm BatchGenerator with per-request samplers
  • Speculative decoding with EAGLE-3 draft models
  • KV cache compression via KIVI 2-bit/4-bit quantization (Metal accelerated)
  • Prefix caching with Aho-Corasick trie for stop/eos/reasoning state tracking
  • Memory management with ProcessMemoryEnforcer and model eviction
