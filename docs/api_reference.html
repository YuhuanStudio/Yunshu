Authentication

Yunshu supports Bearer token authentication. When YUNSHU_AUTH_TOKEN is set, all API requests must include:

Authorization: Bearer <your-token>

If YUNSHU_AUTH_TOKEN is not set, authentication is disabled and any API key is accepted (including "any" in SDK calls).

To explicitly disable auth with a warning log, set YUNSHU_AUTH_DISABLED=true.

Chat Completions OpenAI

POST /v1/chat/completions

Create a chat completion. Supports streaming (SSE), tools, JSON mode, reasoning/thinking output, and logprobs.

model: string required — Model ID (e.g. "Qwen3.5-9B-MLX-4bit")
messages: array required — Conversation messages [{role, content}]
max_tokens: integer optional — Max tokens to generate (default: 4096)
temperature: float optional — Sampling temperature (default: 1.0)
top_p: float optional — Top-p sampling (default: 1.0)
stream: boolean optional — Enable SSE streaming (default: false)
tools: array optional — Tool definitions for function calling
tool_choice: string optional — "auto", "none", or tool name
response_format: object optional — {"type": "json_object"} for JSON mode
stop: array[string] optional — Stop sequences
logprobs: boolean optional — Include log probabilities (default: false)
top_logprobs: integer optional — Number of top logprobs (1-20)
seed: integer optional — Deterministic sampling seed
thinking: object optional — {"type": "enabled", "budget_tokens": N} for reasoning
timeout: integer optional — Request timeout in seconds

Response: {"id", "object", "created", "model", "choices": [{"index", "message": {"role", "content", "tool_calls"}, "finish_reason"}], "usage": {"prompt_tokens", "completion_tokens", "total_tokens"}}

POST /v1/embeddings

Generate text embeddings using MLX-accelerated embedding models.

model: string required — Embedding model ID

Audio OpenAI

POST /v1/audio/speech

Text-to-speech synthesis using MLX-Audio backends (Kokoro, etc.).

model: string required — TTS model ID
input: string required — Text to synthesize
voice: string optional — Voice name (default: "chelsie")
response_format: string optional — "wav" (default), "mp3", "opus"

Response: Binary audio data with Content-Type: audio/wav (or requested format).

POST /v1/audio/transcriptions

Speech-to-text transcription (ASR) via Whisper. Accepts multipart form data.

model: string required — ASR model ID
file: file required — Audio file (wav, mp3, etc.)
language: string optional — Language hint (e.g. "en", "zh")
response_format: string optional — "json" (default), "text", "srt"

Response: {"text": "transcribed text"}

POST /v1/audio/translations

Translate audio to English text.

model: string required
file: file required

Realtime Realtime

POST /v1/realtime

WebSocket upgrade for realtime bidirectional audio/text streaming with ASR + TTS. After upgrade, send/receive JSON events.

Client events: session.update, input_audio_buffer.append, input_audio_buffer.commit, conversation.item.create, response.create

Server events: session.created, session.updated, response.created, response.output_item.added, response.text.delta, response.audio.delta, response.done

GET /v1/realtime/sessions

List active realtime sessions.

Response: {"sessions": [{"id", "created_at", "model"}]}

Streaming Format (SSE)

When "stream": true is set, the server sends Server-Sent Events (SSE) in the following format:

data: {"id":"chatcmpl-123","object":"chat.completion.chunk","created":1694268190,
  "model":"Qwen3.5-9B-MLX-4bit","choices":[{"index":0,"delta":{"content":"Hello"},
  "finish_reason":null}]}

data: {"id":"chatcmpl-123","object":"chat.completion.chunk","created":1694268190,
  "model":"Qwen3.5-9B-MLX-4bit","choices":[{"index":0,"delta":{"content":" world"},
  "finish_reason":null}]}

data: {"id":"chatcmpl-123","object":"chat.completion.chunk","created":1694268190,
  "model":"Qwen3.5-9B-MLX-4bit","choices":[{"index":0,"delta":{},
  "finish_reason":"stop"}]}

data: [DONE]

Stream Chunks

  • Each data: line contains a JSON object with a delta field
  • The delta.content field contains the new text fragment
  • The first chunk may contain delta.role with value "assistant"
  • The final chunk has finish_reason set to "stop", "length", or "tool_calls"
  • The stream terminates with data: [DONE]

Finish Reasons

  • "stop" — Natural stop or stop sequence hit
  • "length" — Max tokens reached
  • "tool_calls" — Model requested a tool call
  • "content_filter" — Content was filtered (if configured)

Error Codes

All errors follow the OpenAI error format:

{
  "error": {
    "message": "Model 'nonexistent' not found",
    "type": "invalid_request_error",
    "param": "model",
    "code": "model_not_found"
  }
}
HTTP Status Error Type Description
400 invalid_request_error Malformed request, missing required fields, or invalid parameters.
401 authentication_error Invalid or missing API key when auth is enabled.
404 model_not_found Requested model is not loaded or does not exist.
429 rate_limit_error Too many requests. Retry after the indicated time.
500 internal_server_error Unexpected server error during generation.
503 engine_error Engine is not initialized or model failed to load.
504 timeout_error Request timed out (controlled by timeout parameter).

Rate Limiting

Rate limiting is configured via YUNSHU_RATE_LIMIT_RPM (requests per minute per client, default: 0 = unlimited).

When rate limited, responses include:

  • 429 Too Many Requests status code
  • X-RateLimit-Limit header — Max requests per minute
  • X-RateLimit-Remaining header — Remaining requests in window
  • X-RateLimit-Reset header — Unix timestamp when window resets
  • Retry-After header — Seconds until retry is allowed
