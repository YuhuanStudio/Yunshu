Development Guide

Setup, project structure, testing, and contributing to Yunshu.

Development Setup

1. Prerequisites

  • macOS with Apple Silicon (M1/M2/M3/M4)
  • Xcode Command Line Tools (xcode-select --install)
  • Python 3.13+ (via uv or system)
  • uv — Python package manager
  • just — Command runner (brew install just)

2. Clone and Setup

git clone https://github.com/YuhuanStudio/yunshu.git
cd yunshu

# Install Python dependencies
just setup

# Or manually:
uv sync

3. Build

# Full build (Metal kernels + Python + WebUI)
just build

# Individual components
just build-metal    # Compile Metal compute shaders
# Python is ready after `uv sync` (no separate build needed)

4. Run Development Server

# Start server with auto-reload
just dev

# With specific model
YUNSHU_MODEL=./models/my-model just dev

# Multi-model mode
YUNSHU_MULTI_MODEL=1 just dev

Tip: Use just dev for development. It runs uvicorn with --reload enabled so code changes are picked up automatically.

Project Structure

yunshu/ justfile # Build orchestration (all commands) pyproject.toml # Python package config, deps, pytest, ruff, mypy python/ # All Python source code (the package) yunshu_gateway/ # L1: FastAPI HTTP server + routers main.py # App factory (create_app), lifespan, middleware engine.py # Module-level engine singleton routers/ # Protocol routers (chat, models, admin...) yunshu_control/ # L2: Scheduling, auth, model registry auth.py # API key validation scheduler.py # Request scheduling model_registry.py # Model discovery and registration hardware.py # Hardware detection (chip, UMA, cores) metrics.py # Prometheus metrics yunshu_api/ # L2: Management API routers yunshu_mesh/ # L3: Compute mesh (mx.distributed) yunshu_engine/ # L4: Inference engine engine.py # Core Engine class (load, start, stop, generate) config.py # EngineConfig dataclass models/ # Modality model handlers yunshu_kv/ # L5: KV cache hierarchy yunshu_sdk/ # Python SDK client library yunshu_cli/ # CLI via Typer metal/ # Metal compute shaders (.metal files) tests/ unit/ # Fast unit tests (no model loading) integration/ # Integration tests (may need models) e2e/ # Full HTTP E2E tests scripts/ # Utility scripts dev_setup.sh # Development environment setup release_prep.py # Release preparation checks benchmark_paper.py # Benchmark paper generator test_e2e_http.py # Live E2E HTTP test test_real_model.py # Real model inference test docs/ # Documentation site (HTML) webui/ # Next.js 16 dashboard (optional)

Package Organization

Each layer is a separate Python package under python/. Dependencies flow downward:

  • yunshu_gateway depends on yunshu_engine (via module-level singleton)
  • yunshu_engine depends on mlx, mlx_lm, mlx_audio (engine primitives only)
  • yunshu_kv depends on mlx (for Metal operations)
  • yunshu_mesh depends on mx.distributed

Import Policy: The engine layer may use mlx/mlx-lm/mlx-audio engine primitives. It must NOT use application-level wrappers like mlx_vlm or mflux.

Testing Guide

Running Tests

# All tests
just test

# Unit tests only (fast, no models needed)
just test-unit

# Single test file
just test-single tests/unit/test_foo.py

# Direct pytest
uv run pytest tests/ -v

# With coverage
uv run pytest tests/ --tb=short -q

Test Categories

  • Unit tests (tests/unit/) — Fast tests with mocked dependencies. No model loading. Should pass on any machine.
  • Integration tests (tests/integration/) — Tests that exercise multiple components together. May require models.
  • E2E tests (tests/e2e/) — Full HTTP request/response tests with mocked engine.

Writing Tests

Follow these conventions:

  • Use pytest fixtures with TestClient from fastapi.testclient
  • Mock the engine using _FakeBatchGen and _FakeTokenizer patterns (see tests/unit/test_e2e_gateway.py)
  • Test both success and error paths (wrong model, missing params, etc.)
  • Use engine_mod._engine to inject fake engine state

Test Example

import pytest
from fastapi.testclient import TestClient
from yunshu_gateway import engine as engine_mod
from yunshu_gateway.main import create_app

def test_my_endpoint():
    """Test my new endpoint."""
    engine_mod._engine = _make_engine()  # inject fake engine
    app = create_app()
    with TestClient(app) as client:
        resp = client.get("/v1/models")
        assert resp.status_code == 200
        data = resp.json()
        assert len(data["data"]) >= 1

Linting & Formatting

# Lint (ruff)
just lint

# Auto-format
just format

# Type check (mypy)
uv run mypy python/

Configuration

  • Ruff: configured in pyproject.toml under [tool.ruff]
  • mypy: configured in pyproject.toml under [tool.mypy]
  • Line length: 88 characters (Black-compatible)
  • Target: Python 3.13

Contributing Guidelines

Workflow

  1. Fork the repository
  2. Create a feature branch: git checkout -b feature/my-feature
  3. Make your changes
  4. Run tests: just test
  5. Run lint: just lint && just format
  6. Commit with a descriptive message
  7. Push and create a Pull Request

Code Style

  • Follow PEP 8 (enforced by ruff)
  • Use type hints on all public functions
  • Add docstrings to classes and public functions
  • Keep functions focused and small (<50 lines preferred)
  • Use structlog for logging (not print)

PR Checklist

  • All tests pass (just test)
  • No lint errors (just lint)
  • New code has tests
  • Public APIs have docstrings
  • Breaking changes are documented
  • No TODO/FIXME left in production code

Architecture Conventions

  • Routers go in yunshu_gateway/routers/ and must be registered in main.py
  • New endpoints should follow existing patterns (see routers/chat.py)
  • Engine changes must maintain thread safety (single Metal thread)
  • All GPU work goes through the ThreadPoolExecutor(max_workers=1)
  • Never pool detokenizers — create one per request
  • Use uv for dependency management (never pip/poetry)

Debugging Tips

Enable Debug Logging

YUNSHU_LOG_LEVEL=DEBUG just dev

Check Engine State

# Health check with engine details
curl http://localhost:8000/health | python -m json.tool

# Model list
curl http://localhost:8000/v1/models | python -m json.tool

# Metrics
curl http://localhost:8000/metrics

Common Issues

  • Model not found (404): Ensure the model is in ./models/ or loaded via the admin API
  • Out of memory: Reduce YUNSHU_MAX_MEMORY_GB or unload unused models
  • Import errors: Run PYTHONPATH=. uv run python -c "import yunshu_gateway"
  • Metal build fails: Ensure Xcode CLI tools are installed: xcode-select --install

Release Process

# Run release preparation checks
PYTHONPATH=. uv run python scripts/release_prep.py

# Skip tests (faster, for quick checks)
PYTHONPATH=. uv run python scripts/release_prep.py --skip-tests

# JSON output
PYTHONPATH=. uv run python scripts/release_prep.py --json

The release prep script validates:

  • Test suite passes
  • All imports are valid
  • Router registration is complete
  • No circular imports
  • TODO/FIXME/HACK count
  • Symbol counts and coverage estimate
