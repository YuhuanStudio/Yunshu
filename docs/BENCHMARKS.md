# Benchmarks

Cross-engine measurements of Yunshu against other local Apple Silicon inference engines on one machine and
one model family, for the 0.1.5 record. This page is generated from the validated measurement records
(`scripts/dev/benchmarks_doc.py`); where a cell has no valid record it says **unknown**, and unknown is never
read as parity or as a win.

- Hardware: Apple M5 Max, 128 GB unified memory, macOS, one engine resident at a time.
- Model: Qwen3.8-27B. Yunshu, TensorFold, mlx-lm, oMLX and MTPLX load the same checkpoint (a 4-bit
  mixed-precision MLX build with an MTP head). Splash and llama.cpp use their own prepared weights
  (a Splash target and a Q4_K_M GGUF with a Q4_0 MTP head); they are product comparisons and are marked with a dagger
  because quantization differences change size and speed.
- Yunshu build measured: the 0.1.4 release (default settings, DFlash speculative decoding engaged, verified from the
  server log for every cell). Later changes on main are not in these numbers.

## Method

- **Corpus.** One frozen prose corpus and one frozen code corpus, generated by a script in the repository. The full
  request, including instructions and chat template, is exactly 1024, 8192, 32768, 65536 or 131072 tokens under the
  checkpoint tokenizer; the length is asserted before sending, and the server-reported prompt tokens are checked.
- **Sampling.** Greedy. Cold requests generate a 2048-token reply and must reach exactly that length with
  `finish=length`; a short reply invalidates the cell. The follow-up turn appends the previous answer and asks for 256 more tokens.
- **Cold, repeated and follow-up.** Cold is the first corpus request in a fresh server session (after two tiny
  startup requests; load time is separate). The repeated request resends the same prompt; the follow-up shares the
  long prefix. Repeated and follow-up TTFT depend on each engine's prefix cache and are reported as measured, with
  no claim about hit coverage unless the engine reports it.
- **TTFT and decode.** TTFT ends at the first streamed content, reasoning or tool delta. Decode tok/s excludes TTFT.
- **Reps and noise.** Each cell is a separate server session with its own load; a number is ranked only with
  three or more independent sessions with identical engine version, checkpoint and mode. The reported noise is the
  median absolute deviation (MAD) across sessions. Parity means the gap to the best engine is within the two engines'
  combined MAD; fewer than three sessions means unknown, not parity.
- **Quiet host.** Timing jobs are admitted only when the host CPU is quiet and are rejected (and rerun) if foreign
  CPU load is recorded during the job. Engines run one at a time on the GPU.
- **Memory.** Host used memory (active + wired + compressor pages) is sampled every two seconds from before the
  server starts; the baseline is taken immediately before launch and the figures are the peak and the value 30 seconds
  after the group, minus that baseline. This counts memory-mapped weights that per-process footprint counters miss.
  It also includes anything else the machine allocates meanwhile, so treat differences of a few GiB as noise.
- **Failures.** A cell with a failed, incomplete or contended run is excluded and rerun; an engine that cannot
  complete a cell is listed as unknown for that cell and the reason is recorded, not hidden.
- **Concurrency and long-context QA.** Two, four and eight simultaneous 32K requests (effective throughput includes
  prefill) and ten deterministic needle questions at 32K, 64K and 128K.

Hypotheses about causes are not profiler-established findings. Reproduction scripts are under `scripts/research/`
(`gen_snapshot_prompts.py`, `bench_snapshot.py`) and the `yv` verification driver (`scripts/dev/yv`, suite `snapshot`).
