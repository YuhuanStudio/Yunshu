title: Evals
description: The OpenAI Evals API on a local store - define graders, run them over JSONL or stored completions, and read per-item results.
---

The `/v1/evals` routes follow the OpenAI Evals API. An eval describes a data schema and a list of graders (`testing_criteria`). A run feeds rows through those graders, optionally sampling a model first, and records an output item per row plus pass/fail counts. Everything is stored as JSON under `~/.yunshu/evals` (`YUNSHU_EVALS_DIR` changes the directory).

Runs execute inside the server process in the background. Sampling and model-based graders call this server's own Chat Completions route in-process, so they use the same loaded models, auth and sampling behaviour as normal requests.

## Create an eval

`POST /v1/evals` takes a JSON body that must also pass the OpenAI SDK's `EvalCreateParams` type check.

| Parameter | Type | Required | Description | Status |
| --- | --- | --- | --- | --- |
| `name` | string | no | Display name. | supported |
| `metadata` | object | no | Up to 16 string key-value pairs. | supported |
| `data_source_config` | object | yes | `{"type": "custom", "item_schema": {...}, "include_sample_schema": bool}`. `type` may also be `stored_completions` or `logs`. | partial |
| `testing_criteria` | array | yes | Non-empty list of graders, with unique non-empty `name` values. | supported |

`custom` requires `item_schema`, which must be a valid JSON Schema (Draft 2020-12); every row's `item` is validated against it when a run is created. The stored `data_source_config` is returned as `{"type", "schema"}` where `schema` wraps your `item_schema` under `item` (and adds a `sample.output_text` property when `include_sample_schema` is true).

### Graders

| Grader `type` | Fields | What it does |
| --- | --- | --- |
| `string_check` | `name`, `input`, `reference`, `operation` (`eq`, `ne`, `like`, `ilike`) | Compares two template strings. `like` means `reference` is a substring of `input`; `ilike` ignores case. Score is 1 or 0. |
| `text_similarity` | `name`, `input`, `reference`, `evaluation_metric`, `pass_threshold` | Lexical similarity computed locally with no model. Metrics: `cosine`, `fuzzy_match`, `bleu`, `gleu`, `meteor`, `rouge_1` to `rouge_5`, `rouge_l`. Passes when the score reaches `pass_threshold`. |
| `score_model` | `name`, `model`, `input` (messages), optional `range` (default `[0, 1]`), `pass_threshold`, `sampling_params` | A model returns a number in `range`; passes when the score reaches `pass_threshold` (default 1). |
| `label_model` | `name`, `model`, `input` (messages), `labels`, `passing_labels`, `sampling_params` | A model returns one of `labels`; passes when the label is in `passing_labels`. |

Grader fields are templates: `{{item.field}}` and `{{sample.output_text}}` placeholders are replaced from the row (nested paths and list indexes use dots). An unknown reference fails that row with an error. The lexical metrics are Yunshu's own implementations: cosine uses token frequencies, METEOR uses exact-token alignment without a synonym corpus, and BLEU is sentence BLEU without smoothing, so scores can differ slightly from other implementations.

Model graders ask for structured JSON output (a `score` number or a `label` string) through the local `response_format` JSON Schema path, then validate it.

Any other grader type, such as `python` or `endpoint`, returns `400`.

## Update, list, delete evals

- `POST /v1/evals/{eval_id}` updates `name` and `metadata`.
- `GET /v1/evals` takes `limit` (1 to 100, default 20), `order` (`asc` or `desc`, default `desc`), `after` and `order_by` (`created_at` or `updated_at`).
- `DELETE /v1/evals/{eval_id}` deletes the eval, cancels and removes all its runs, and returns `{"object": "eval.deleted", "deleted": true, "eval_id": ...}`.

Lists return `{"object": "list", "data", "has_more", "first_id", "last_id"}`. An unknown `after` cursor returns `400`.

## Create a run

`POST /v1/evals/{eval_id}/runs` takes a body validated against the SDK's `RunCreateParams`:

| Parameter | Type | Required | Description | Status |
| --- | --- | --- | --- | --- |
| `name`, `metadata` | | no | Display name and up to 16 string pairs. | supported |
| `data_source.type` | string | yes | `jsonl` (grade the rows as given) or `completions` (sample a model first). Other types return `400`. | partial |
| `data_source.source` | object | yes | Where the rows come from, see below. | supported |
| `data_source.model` | string | no | With `type: "completions"`, the model to sample. Without it the rows' own `sample` is graded. | supported |
| `data_source.input_messages` | object | with `model` | `{"type": "template", "template": [messages]}` or `{"type": "item_reference", "item_reference": "item.input"}`. | supported |
| `data_source.sampling_params` | object | no | Passed to Chat Completions (`temperature`, `top_p`, `seed`, `max_completion_tokens`, ...). | supported |

Row sources (`data_source.source.type`):

| Source | Fields | Notes |
| --- | --- | --- |
| `file_content` | `content`: array of `{"item": {...}, "sample": {...}}` | Inline rows. |
| `file_id` | `id` of a file in the [Files](/docs/api/files) store | JSONL file, one row per line, same row shape. |
| `stored_completions` | optional `model`, `metadata`, `created_after`, `created_before`, `limit` | Rows built from Chat Completions stored by this server (see [Stored completions](/docs/api/stored-completions)). `limit` is 1 to 10000. |

At most 10,000 rows; every `item` must match the eval's `item_schema`. A bad source fails the create call with `400` before anything runs.

The call returns the run immediately with `status: "queued"`; the work happens in the background.

```json
{
  "id": "evalrun_0a1b2c3d4e5f60718293a4b5",
  "object": "eval.run",
  "created_at": 1767225600,
  "eval_id": "eval_9f8e7d6c5b4a39281716f5e4",
  "name": "",
  "model": "local",
  "status": "queued",
  "error": null,
  "report_url": "",
  "metadata": null,
  "per_model_usage": [],
  "per_testing_criteria_results": [
    { "testing_criteria": "exact", "passed": 0, "failed": 0 }
  ],
  "result_counts": { "total": 0, "passed": 0, "failed": 0, "errored": 0 },
  "data_source": { "type": "completions", "model": "local" }
}
```

Run `status` values: `queued`, `in_progress`, `completed`, `canceled`, `failed`. Rows are processed one at a time. A restart fails runs that were queued or in progress (`error.code` is `interrupted`); create a new run to retry. `report_url` is always empty.

## Runs and output items

- `GET /v1/evals/{eval_id}/runs` takes `status`, `limit`, `order` (default `asc`) and `after`.
- `GET /v1/evals/{eval_id}/runs/{run_id}` returns the run with its running counts and per-model token usage.
- `POST /v1/evals/{eval_id}/runs/{run_id}/cancel` cancels a queued or in-progress run (status becomes `canceled`); finished runs are returned unchanged.
- `DELETE /v1/evals/{eval_id}/runs/{run_id}` cancels and deletes it and returns `{"object": "eval.run.deleted", "deleted": true, "run_id": ...}`.
- `GET .../output_items` lists items; `status` filters on `pass` or `fail`. `GET .../output_items/{output_item_id}` returns one.

An output item:

```json
{
  "id": "evalitem_0a1b2c3d4e5f60718293a4b5",
  "object": "eval.run.output_item",
  "created_at": 1767225610,
  "eval_id": "eval_9f8e7d6c5b4a39281716f5e4",
  "run_id": "evalrun_0a1b2c3d4e5f60718293a4b5",
  "datasource_item_id": 0,
  "datasource_item": { "question": "2+2?", "answer": "4" },
  "sample": {
    "model": "local",
    "input": [{ "role": "user", "content": "2+2?" }],
    "output": [{ "role": "assistant", "content": "4" }],
    "finish_reason": "stop",
    "usage": { "prompt_tokens": 14, "completion_tokens": 2, "total_tokens": 16, "cached_tokens": 0 },
    "error": null
  },
  "results": [
    { "name": "exact", "type": "string_check", "score": 1.0, "passed": true }
  ],
  "status": "pass"
}
```

`status` is `pass` when every grader passed, `fail` when at least one did not, and `error` when the row failed (for example a template reference was missing or a model call failed); the message is in `sample.error`. Error items are counted under `result_counts.errored` and are not returned by the `pass`/`fail` filter.

<Tab value="Python">

```python
import time
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8000/v1", api_key="not-needed")

ev = client.evals.create(
    name="arith",
    data_source_config={
        "type": "custom",
        "item_schema": {
            "type": "object",
            "properties": {"question": {"type": "string"}, "answer": {"type": "string"}},
            "required": ["question", "answer"],
        },
        "include_sample_schema": True,
    },
    testing_criteria=[
        {
            "type": "string_check",
            "name": "exact",
            "input": "{{sample.output_text}}",
            "operation": "eq",
            "reference": "{{item.answer}}",
        }
    ],
)

run = client.evals.runs.create(
    ev.id,
    name="run-1",
    data_source={
        "type": "completions",
        "model": "local",
        "input_messages": {
            "type": "template",
            "template": [{"role": "user", "content": "{{item.question}} Answer with just the number."}],
        },
        "source": {"type": "file_content", "content": [{"item": {"question": "2+2?", "answer": "4"}}]},
    },
)

while run.status in ("queued", "in_progress"):
    time.sleep(1)
    run = client.evals.runs.retrieve(run.id, eval_id=ev.id)
print(run.result_counts)
```

## Errors

Errors use the OpenAI envelope with codes such as `invalid_value`, `invalid_type`, `not_found` and `unsupported_value`.

| Status | When |
| --- | --- |
| `400` | Body does not match the SDK types, unsupported `data_source_config`, grader or data source type, invalid JSON Schema, bad template, more than 10,000 rows, a row that violates `item_schema`, bad pagination or filter value. |
| `404` | Unknown eval, run, output item or file. |

Failures that happen while a run executes do not change the HTTP status. They appear as `error` output items, or as `status: "failed"` with `error` on the run.

## Support

| Feature | Status |
| --- | --- |
| Eval CRUD, runs, output items, cancel | <Support status="supported">supported</Support> |
| Graders `string_check`, `text_similarity`, `score_model`, `label_model` | <Support status="supported">supported</Support> |
| Graders `python`, `endpoint`, `multi` | <Support status="unsupported">rejected with 400</Support> |
| Run data sources `jsonl` and `completions` | <Support status="supported">supported</Support> |
| Run data sources `responses`, `logs` and others | <Support status="unsupported">rejected with 400</Support> |
| `data_source_config.type: "logs"` | <Support status="partial">accepted for the eval, but no run source reads logs</Support> |
| Parallel rows | <Support status="unsupported">rows run one at a time</Support> |
| Resuming a run after restart | <Support status="unsupported">interrupted runs are marked failed</Support> |
| `report_url` | <Support status="unsupported">always empty</Support> |
