Yunshu 优先处理 Apple Silicon 上快速的本机 LLM 与 VLM 推理：解码速度、冷启动与命中缓存时的首 token 延迟、前缀复用，以及完整的客户端行为。Qwen3.8-27B 是第一个调优完成的模型。本页记录的是方向，不含日期，也不代表相关工作已经上线。已发行的行为属于 changelog；实测结果属于[性能基准](/docs/guides/benchmarks)。

## 优先事项

| 优先级 | 工作 | 完成证据 |
|---|---|---|
| 现在 | 缩小 27B 与 Flash-Next 已实测到的长 context 差距 | 在 32K、64K 与 128K 分别比较冷、暖与后续请求的首 token 时间及解码；目前的差距见[性能基准](/docs/guides/benchmarks) |
| 下一步 | Apple Silicon 可移植性证据 | 记录 M1 到 M5 与 macOS 的检查，区分通过、失败与未测试的组合 |
| 下一步 | 模型与客户端能力证据 | 针对特定 checkpoint 与客户端版本的结果；不支持的功能会返回可操作的错误提示 |
| 下一步 | 可重现的性能数据发布 | 同一 checkpoint 的冷、暖与第二回合运行，附正确性检查与原始收据链接 |
| 之后 | 更广泛的模型调优 | 在不降低输出正确性的前提下，取得实测的端到端收益 |

音频、语音、图像与视频生成，以及 embeddings 仍是支持的能力。共用路径上的退步，以及明确列为优先的工作，会优先处理。分布式服务与多租户基础设施不在范围内。

## 轻量 RFC 流程

例行修正走普通的贡献与审查流程（见[贡献指南](/docs/developers/contributing)）。对于公开 API、配置、缓存格式、支持硬件或架构的重大变更，实现前请先记录提案，内容包含：

- 用户的问题与具体提议的行为；
- 范围、替代方案与选择的理由；
- 兼容性、迁移、隐私与失败时的行为；
- 正确性检查、决定成败的测量方式，以及回滚计划；
- 负责人、状态（proposed、accepted、implemented 或 superseded）与决定的理由。

可使用现有的讨论，或可供审查的 Markdown 提案；小修正不需要另开 issue。维护者在审查提案的地方记录决定。Accepted 不代表已上线：请附上实现与验证的链接，再关闭提案。涉及安全漏洞的细节请依 `SECURITY.md` 私下报告，不要写在公开提案中。

## 决策与维护

贡献者要对自己变更的质量与说明负责。维护者审查范围、兼容性与证据；仓库管理员控制合并、发行与访问权限。审查者应指出尚未解决的异议，并记录最后选择的取舍。治理方面的变更需要明确的维护者审查；本页不授予仓库权限，也不创建新的角色。
