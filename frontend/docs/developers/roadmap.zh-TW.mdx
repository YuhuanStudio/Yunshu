Yunshu 優先處理 Apple Silicon 上快速的本機 LLM 與 VLM 推論：解碼速度、冷快取與熱快取的首 token 延遲、前綴重用，以及完整的客戶端行為。Qwen3.8-27B 是第一個調校完成的模型。本頁記錄的是方向，不是日期，也不宣稱工作已經上線。已發行的行為屬於 changelog；量測結果屬於[效能基準](/docs/guides/benchmarks)。

## 優先事項

| 優先度 | 工作 | 完成證據 |
|---|---|---|
| 現在 | 縮小 27B 與 Flash-Next 已量測到的長 context 差距 | 在 32K、64K 與 128K 分別比較冷、熱與後續請求的首 token 時間及解碼；目前的差距見[效能基準](/docs/guides/benchmarks) |
| 下一步 | Apple Silicon 可攜性證據 | 記錄 M1 到 M5 與 macOS 的檢查，區分通過、失敗與未測試的組合 |
| 下一步 | 模型與客戶端能力證據 | 針對特定 checkpoint 與客戶端版本的結果；不支援的功能給出可據以處理的錯誤 |
| 下一步 | 可重現的效能發布 | 同一 checkpoint 的冷、熱與第二回合執行，附正確性檢查與原始收據連結 |
| 之後 | 更廣泛的模型調校 | 在不降低輸出正確性的前提下，取得端對端的量測收益 |

音訊、語音、圖像與影片生成，以及 embeddings 仍是支援的能力。共用路徑的退化與明確列為優先的工作優先處理。分散式服務與多租戶基礎設施不在範圍內。

## 輕量 RFC 流程

例行修正走一般的貢獻與審查流程（見[貢獻指南](/docs/developers/contributing)）。對於公開 API、設定、快取格式、支援硬體或架構的重大變更，實作前請先記錄提案，內容包含：

- 使用者的問題與具體提議的行為；
- 範圍、替代方案與選擇的理由；
- 相容性、遷移、隱私與失敗時的行為；
- 正確性檢查、決定成敗的量測，以及回滾計畫；
- 負責人、狀態（proposed、accepted、implemented 或 superseded）與決定的理由。

可使用既有的討論，或可供審查的 Markdown 提案；小修正不需要另開 issue。維護者在審查提案的地方記錄決定。Accepted 不等於已上線：請附上實作與驗證的連結來關閉提案。私下回報的安全漏洞細節依 `SECURITY.md` 處理，不放在公開提案中。

## 決策與維護

貢獻者對自己變更的品質與說明負責。維護者審查範圍、相容性與證據；儲存庫管理員控制合併、發行與存取權限。審查者應指出尚未解決的異議，並記錄所選擇的取捨。治理方面的變更需要明確的維護者審查；本頁不授予儲存庫權限，也不建立新的角色。
