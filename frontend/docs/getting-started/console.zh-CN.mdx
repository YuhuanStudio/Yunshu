主控台是由它自己的轻量进程（`yunshu console`，端口 8100）提供的网页应用，与引擎分开运行。这个进程提供主控台与这份文档、把主控台的 API 调用转发给引擎，并记录历史，所以引擎重启或崩溃时，主控台仍可使用、仍持续记录。它是观察单个引擎的窗口：实时状态、请求、模型、缓存、日志、API 密钥、设置与这份文档。它不负责启动引擎，也不是聊天产品。

<Callout type="info">
主控台支持繁体中文、简体中文与英文，默认跟随浏览器语言，选择会保存在浏览器；可从顶部栏的语言按钮切换。这份文档也跟随同一个选择。
</Callout>

## 打开主控台

照常启动服务：`yunshu serve` 会在引擎旁边启动主控台进程。在浏览器打开主控台端口的 `/console/`，默认是 `http://127.0.0.1:8100/console/`（引擎保持 8000）。`--no-console` 可跳过、`--console-port` 可更换端口，`yunshu console --engine http://host:8000` 可单独运行，例如监看另一台机器上的引擎。`yunshu service install` 会把它安装成独立的 launchd job，引擎重启期间它仍持续服务与记录。旧的 `http://127.0.0.1:8000/console/` 在一个版本内仍可使用，会跳转到主控台进程。

静态页面是公开的，这样你才能在浏览器输入令牌。主控台发出的每个 API 调用仍遵守一般认证规则：默认的本机服务不需要令牌就能读取状态、历史、请求、模型与缓存视图；管理页面（API 密钥、日志、服务、CORS）需要管理员令牌，缺少时会显示提示并链接到设置。请在“设置”输入 `YUNSHU_AUTH_TOKEN` 或管理员密钥；默认只保存在页面内存，刷新后即清除。

若 `/console/` 返回 404 并显示 “Yunshu Console is not built”，说明已安装的软件包不含主控台构建，API 不受影响。从源码运行时，用 Node.js 22.18 以上与 pnpm 构建：

```bash
cd frontend
pnpm install --frozen-lockfile
pnpm build
```

构建结果写入 `python/yunshu_gateway/console_static`，由主控台进程提供。

## 页面

侧边栏有六区：总览、请求、诊断、模型、推理测试与设置。日志在诊断分页；下载与缓存在模型分页；密钥与 API 访问在设置分页。文档从顶部栏打开，原有分页地址仍有效。

| 页面 | 功能 |
|---|---|
| 引擎总览 | 实时引擎状态：阶段（排队、预填充、解码）、吞吐量、内存、缓存与进行中的请求。请求运行时每秒更新约四次，空闲时放慢。 |
| 请求与性能 | 进行中与已结束的请求，含各阶段时间线、token 与缓存细节、筛选、CSV 导出与单个取消。 |
| 日志 | 服务器日志环，可按级别与文字筛选并实时追尾。 |
| 引擎诊断 | 健康检查、主机读数、支持包预览与原始诊断数据。 |
| 模型库 | 已加载与可用的模型及内存数字；加载、卸载、预热、容量检查与空闲保留。 |
| 下载 | 从 Hugging Face 下载模型，附进度、磁盘空间检查与取消。 |
| 缓存 | 前缀缓存各层（内存、暖层、SSD）的条目、生命周期事件与清除操作。 |
| 推理测试 | 流式对话，含生成设置、工具、图片、token 置信度与生成代码片段。 |
| API 接入 | 你的服务连接片段，以及它注册的路由目录。 |
| 文档 | 这些页面，可从命令面板搜索。 |
| 密钥 | 具名 API 密钥：权限范围、到期时间、滚动日配额与各密钥用量。 |
| 设置 | 服务地址与令牌、主题与语言、每个引擎设置及其来源、CORS 与服务重启。 |

## 历史，以及引擎离线时

主控台进程每秒读取一次引擎，把历史保存在 `~/.yunshu/console-history.sqlite`：最近一小时 1 秒分辨率、24 小时 10 秒、30 天 1 分钟，另有已结束请求的记录（只有数字，从不保存提示词或输出）。打开时，图表（15 分钟到 30 天）与请求列表会先从这里回补，再接上实时数据。引擎连不上的期间不会记录，所以那一段会显示为缺口与事件（“引擎无法连接”“引擎恢复连接”“引擎重新启动”“模型加载失败”），绝不会画一条线穿过去。

引擎没有响应时，主控台会显示“引擎自 18:02:11 离线，4 秒后重试”并持续重试（退避到约十秒，回到标签页或网络恢复时立即重试）。显示引擎数据的页面保留最后的数据，变暗并标示为过期；文档与设置不受影响。引擎在线但模型加载失败时，页面显示错误，“加载模型”仍可使用。单个页面出错不会让整个主控台挂掉。

## 状态与状态栏

桌面页面底部独立的浮动状态胶囊显示引擎状态、已加载模型与内存。点击它（手机上是精简胶囊）会展开状态岛：实时阶段、吞吐量、各所有者的内存与主机信息。服务器没有上报的值显示为无法获取，而不是 0。

刷新失败时，主控台保留上一次的数字并注明；连不上引擎时会显示离线横幅，附“重试”与“连接设置”。

## 命令面板

按 `⌘K`（其他系统为 `Ctrl K`）打开命令面板：可跳到页面、执行加载模型或清除缓存等操作、切换语言，也能搜索这份文档，输入两个字以上，匹配的页面与段落会列在“文档”之下。按 `?` 可查看键盘快捷键。

## 连接设置

默认情况下，主控台连接提供它的同一个来源。你可以在“设置”改为指向另一台 Yunshu 服务；该服务必须通过 CORS 配置（`YUNSHU_CORS_ORIGINS`，有管理员令牌时可在设置页编辑）允许主控台的来源。浏览器只保存服务地址、主题与语言；令牌只有在你要求时才保存。

## 通知

顶部栏的铃铛会打开通知中心（通知）。它按时间由新到旧列出主控台在监视期间发生的变化，最多 50 条；徽标显示未读数量，打开面板即标为已读，「清除全部」会清空。每一行都链接到能说明该事件的页面。

| 事件 | 触发时机 | 前往 |
|---|---|---|
| 模型已加载／模型加载失败 | 两次状态读取之间，模型的已加载或错误状态改变 | 模型 |
| 下载完成／下载失败 | 排队中或进行中的下载结束 | 下载 |
| 引擎无法连接／引擎已恢复连接 | 引擎停止或恢复响应 | 诊断／总览 |
| 引擎已重启 | 上报的运行时间倒退 | 诊断 |
| 内存压力偏高 | Metal 使用中内存达统一内存的 80%；回落 5 个百分点后解除 | 模型 |
| 服务器错误增加 | 一分钟内出现 3 个以上 5xx 响应；每 5 分钟最多一次 | 请求 |

只有警告与错误会另外弹出提示消息，其余静静留在通知中心。打开页面后的第一次读取不会产生任何通知，打开前已完成的下载也不会被通知。

<Callout type="info">
这些事件是浏览器根据主控台本来就在读取的状态、请求与下载数据推算出来的。它们按服务器地址存放在 `sessionStorage`，刷新标签页后仍在，但新开标签页就不会，也不会发给服务器。这与主控台进程记录的历史及其引擎事件是两回事。
</Callout>

## 内存账本

内存账本回答「统一内存被谁占用」。数据来自引擎的 `/v1/yunshu/memory`（需要推理权限），页面可见时主控台每隔数秒重新读取。它出现在三个地方：

- **模型**：某个模型的详细信息中的「内存持有者」。
- **状态岛**：Metal 内存区块（连同 Swap、内存压力与保留池）。
- **缓存**：前缀缓存的占用量会标示「来自内存账本」。

表格（持有者、大小、可回收）列出模型权重、前缀缓存（内存）、前缀缓存（暖层）、进行中请求的 KV、内存保留池与其他，并以一条对照 Metal 内存的条形呈现。标记线显示自服务器启动以来的峰值、Metal 建议上限与 wired 上限。

- 服务器没有计数器的大小会显示「未知」，而不是 0；估算值会标示「估算」。
- 各持有者合计超过 Metal 使用中内存时，「其他」显示 0，并说明超出的量。
- 没有此路由的引擎会显示「此引擎版本没有提供内存持有者明细」，并停止轮询。

各持有者如何计算，请见[内存](/docs/internals/memory)。

## 推测解码与阶段延迟

两个面板都在「请求」页，读取引擎的已完成请求记录（`/v1/yunshu/requests/recent`）。

**推测解码**位于请求列表下方。它先说明最近已完成的请求中有多少上报了推测解码，再按「模式」分组，显示请求数、接受率（已接受 token 总数除以草稿 token 总数，只计入两个计数器都有上报的请求）、接受／草稿 token 与轮数；复制草稿（copy-draft）轮次会另外标出。没有推测解码记录的请求视为普通解码，有模式但没有计数器的请求则不纳入比率。引擎目前只上报每个请求的总数，所以没有逐深度图表。第二个区块「引擎累计计数器」（模型、MTP 周期、接受、拒绝、自适应草稿）读自 `/debug/spec-decode`，涵盖引擎启动以来的全部；若 `/debug` 关闭，会说明引擎未提供。

**阶段延迟**是请求瀑布图，显示在单个请求的详细信息中。阶段有模型租用、网关准入、引擎排队、模板与分词、前缀缓存还原、预填充、首个解码与首次发送，时间零点是网关收到请求的时刻。

<Callout type="warn">
引擎没有观测到的阶段会列在「未上报」，绝不画成 0。预填充结束是主机端回调的边界，不是 GPU 剖析；模板与分词包含媒体预处理；首次发送是服务器发完数据，不代表客户端已收到。由页面根据状态轮询拼出、没有引擎记录的行没有瀑布图，较旧的引擎则会显示「这个引擎还没有提供阶段延迟」。引擎有主机遥测时，详细信息还会显示预填充与解码区间的能耗估算，其中包含其他进程与空闲功耗。
</Callout>

## Realtime 连接健康

在「诊断」页，「Realtime 连接」卡片（测试连接）检查从这个浏览器到引擎 Realtime WebSocket（`/v1/realtime`，按页面使用 `ws` 或 `wss`）的路径。它只打开一次连接并等待第一个事件，然后显示建立连接、第一个事件、服务器延迟与缓冲深度，并标明各项来自浏览器或服务器。它不发送音频、不使用 GPU，所以证明的是连得上，而不是语音质量；引擎没有上报的数值会省略，不会显示成 0。请见 [Realtime API](/docs/api/realtime)。

## 工具测试与图片识别

两者都从 Playground 工具栏打开，并使用该处选定的模型。

### 工具测试

「工具测试」打开工具调用与结构化输出测试。在「工具调用」标签页粘贴 JSON 格式的工具定义（输入时实时检查：名称为 1 到 64 个字母、数字、下划线或连字符，`parameters` 为 object schema），输入提示词后点「发送第一轮」。每一轮都会显示引擎是否调用了工具，以及参数是否为合法 JSON、是否指向你定义的工具、是否符合 schema。填入结果并点「送回结果并继续」进入下一轮，直到轮数上限；「重新开始」会重置。在「结构化输出」标签页提供 JSON schema 后发送，回复会检查是否为 JSON 并是否符合 schema。页面只检查 JSON Schema 的一个子集，并列出跳过的关键字；响应也不会说明引擎是否用受限解码强制执行 schema，这里只检查结果。请求会发送到 `/v1/chat/completions`。请见[结构化输出](/docs/guides/structured-output)。

### 图片识别

「图片识别」对话框接受 10 MB 以内的 PNG、JPG、WEBP、TIFF 或 BMP，发送到 `/v1/ocr`，显示识别出的文本、模型与 token 用量。没有任何已加载模型能响应时，按钮停用并提示「没有加载 OCR 或视觉模型，无法使用图片识别」；优先使用 OCR 类模型，否则用第一个已加载的视觉模型。图片只发给引擎，不会被保留。引擎只返回文本，所以不会在图片上标出位置，也没有置信度数值。请见 [OCR API](/docs/api/ocr)。

## 引擎固定、自动发现与测量暂停

这些功能属于主控台进程（`yunshu console`），请见[主控台进程](/docs/internals/console-process)。

- **自动发现。**`yunshu console --engine auto`（或 `YUNSHU_CONSOLE_ENGINE=auto`）让同一个主控台在引擎重启与更换端口时保持打开。每隔 `YUNSHU_CONSOLE_DISCOVER_S` 秒（默认 2）用 `/health` 探测候选端口；`YUNSHU_CONSOLE_DISCOVER_PORTS=all`（默认）会取这台 Mac 上所有正在监听的 TCP 端口，也可以指定列表，例如 `8000,18990-18999`。只有响应方式像 Yunshu 引擎的端口才算数。它会留在当前跟随的引擎上，连续两次探测失败后才改跟最近启动的存活引擎。
- **固定。**状态岛会列出存活的引擎（引擎：端口、模型、运行时间）。「使用」会固定其中一个，只要它还活着就优先；「改为跟随最新」则取消固定。也可通过主控台进程的 engines 路由操作（`/console/api/engines`，也可从 `/v1/yunshu/console/engines` 访问）。
- **等待。**没有存活的引擎时，状态岛显示「等待引擎启动」，引擎一启动主控台就会连上；短暂的中断会以重启的平静样式呈现，而不是当成故障。
- **测量暂停。**`YUNSHU_CONSOLE_PAUSE_FILE` 指定的文件内容为 `{"pause": true, "until": ..., "reason": "..."}` 期间，主控台不轮询也不探测任何引擎，监控就不会干扰计时实验，状态岛会显示「因测量暂停：原因」。你自己发出的请求仍会通过。暂停在 `until` 到期、`until` 为 null 时于文件最后写入两小时后，或文件被移除时结束。

<Callout type="info">
请求历史会连同每个请求记下引擎 URL 与启动时间，所以切换引擎会呈现为独立的会话，并以 `engine_switched` 事件标示。
</Callout>

## 网络与 CORS

「设置」有一个「网络与 CORS」标签页，修改需要管理令牌。

- **网络**是只读的：显示控制台连接的地址，以及可访问范围（仅本机或局域网可访问）。它会显示切换用的 `yunshu service install --force --host 127.0.0.1` 或 `--host 0.0.0.0` 命令，因为监听地址要重新安装服务才能变更。开放局域网之前，请先设置 `YUNSHU_AUTH_TOKEN` 或创建 API 密钥，并只允许你需要的来源。
- **CORS 来源**编辑哪些网站可以从浏览器调用这个服务器。添加来源时写成 `http://` 或 `https://` 加主机、不含路径，或单独一个 `*`；`*` 不能与其他来源并用，且需要明确确认，因为它会让任何网站调用服务器（不带凭证）。页面会说明这个主控台自己的来源是否被允许。保存立即生效；「恢复默认」会还原默认。
- 如果列表由 `YUNSHU_CORS_ORIGINS` 或命令行标志设置，会优先于配置文件：编辑器会提示这点，编辑会被保存，但不会改变正在运行的值。

完整的 CORS 规则请见[验证与密钥](/docs/guides/auth-and-keys)。

## 主控台不做的事

- 它不是多用户控制平面：密钥的权限范围与配额只针对这一台本机服务。
- 它不保存长期的对话历史；推理测试的资料库只存在你的浏览器。
- 请求视图从不保存提示词与回复，只有元数据。
