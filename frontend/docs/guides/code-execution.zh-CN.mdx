Anthropic 的 `code_execution_20250522`、`_20250825`、`_20260120` 与 `_20260521` 工具会在这台机器上、Anthropic 的 [sandbox-runtime](https://github.com/anthropics/sandbox-runtime)（`srt`）内运行。此功能默认为关闭。沙箱如何构建，请见[代码执行沙箱](/docs/internals/code-execution-sandbox)。

## 启用

<Steps>
<Step>

安装沙箱运行环境。需要 Node 22.12 或更新版本，`srt` 是可选依赖。

```bash
npm install -g @anthropic-ai/sandbox-runtime
```

</Step>
<Step>

启用代码执行并启动服务：

```bash
yunshu serve -m <model> --set code_execution=1
```

</Step>
<Step>

运行 `yunshu doctor`，查看“code execution”那一列，会显示 `srt` 版本与自我测试结果。

</Step>
</Steps>

| 设置 | 默认 | 意义 |
|---|---|---|
| `YUNSHU_CODE_EXECUTION` | `false` | 提供此工具。关闭时：声明它的请求会得到指出此设置的 `400`。开启但没有 `srt` 时：返回 `503`（`api_error`）并附安装命令。命令绝不会在 `srt` 之外运行。 |
| `YUNSHU_CODE_EXECUTION_ROOT` | `~/.yunshu/sandbox` | 每个容器一个子目录，权限 0700。 |
| `YUNSHU_CODE_EXECUTION_TIMEOUT` | `60.0` 秒 | 每次调用的挂钟时间（同时也是 CPU 时间上限）；超时为 `execution_time_exceeded`。 |
| `YUNSHU_CODE_EXECUTION_MEMORY_MB` | `2048` | 该次调用整个进程组的常驻内存，每 100 ms 采样一次；超过就终止该调用。 |
| `YUNSHU_CODE_EXECUTION_NETWORK_ALLOW` | 未设置 | 沙箱可连接的主机，以逗号分隔（`example.com`、`*.example.com`、`host:443`）。未设置：完全没有网络，包含 loopback。 |
| `YUNSHU_CODE_EXECUTION_TTL_MIN` | `20.0` | 容器闲置多少分钟后，连同其文件一并删除。 |

## 从 Messages API 使用

在 [Messages](/docs/api/messages) 请求中声明此工具，不需要 beta 标头：

```json
{"type": "code_execution_20250825", "name": "code_execution"}
```

模型会得到两个子工具：`bash_code_execution` 与 `text_editor_code_execution`（`view`、`create`、`str_replace`）。响应会按 Anthropic 文档带有 `server_tool_use` 块，以及 `bash_code_execution_tool_result` 或 `text_editor_code_execution_tool_result` 块。流式输出的方式相同：子工具输入以 `input_json_delta` 发送，每个结果块则整个放在一个 `content_block_start` 中。响应也带有 `container: {id, expires_at}`（流式输出时位于 `message_delta.delta`）。

- **容器。** 将 `container: "<id>"`（或 `{id}`）传回即可保留工作目录。未知或已过期的 id 会是 `400`。容器在闲置 TTL 后删除，总量上限为 2 GiB（最旧的先删）。
- **文件。** `container_upload` 内容块会把 [Files API](/docs/api/files) 的文件复制到工作目录。每次 bash 调用都有全新的 `$OUTPUT_DIR`；其顶层文件会变成 Files API 条目，以 `bash_code_execution_output {file_id}` 返回（用 `GET /v1/files/{id}/content` 下载）。
- **输出限制。** stdout 与 stderr 各自在 64 KiB 截断（并标记）。stdout 与 stderr 合计超过 1 MiB 的调用会被终止（`output_file_too_large`）。后台进程会随该次调用结束。命令看到的环境变量只有 `PATH`、`HOME`（容器）、`TMPDIR`、`OUTPUT_DIR` 与区域设置变量，绝不包含服务器的环境。

## Python、REPL 状态与程序化工具调用

`20250522` 只有一个 Python 工具（`code_execution`，每次调用全新进程）。`20250825` 有 bash 与文本编辑器（客户端工具在 `allowed_callers` 列出代码执行调用者时再加 Python，同样每次全新）。`20260120` 与 `20260521` 三者皆有，且 Python 进程与容器同生命周期：变量与 import 在调用之间保留。超时、内存超限、输出超过 1 MiB、闲置 10 分钟、删除容器，或超过四个容器各持有一个进程时，进程会被杀掉并干净地重启。

工具若设 `"allowed_callers": ["code_execution_20260120"]`，就成为解释器中的 `async` Python 函数。代码 await 它时，该回合以 `stop_reason: "tool_use"` 结束，每个调用一个带 `caller: {type, tool_id}` 的 `tool_use` 块。带着 `container` 把结果送回，响应就接着给出 `code_execution_tool_result`。cell 最多等待 270 秒；单个 cell 最多 256 次调用。

## OpenAI Responses 与容器

同一个设置下，[Responses](/docs/api/responses) 请求可声明 `{"type": "code_interpreter", "container": {"type": "auto"}}`（或 `cntr_` id）与托管的 `{"type": "shell", "environment": {"type": "container_auto"}}`。响应有 `code_interpreter_call`、`shell_call`、`shell_call_output` 项目、对应的流式事件，以及代码生成的文件的 `container_file_citation` 注解；后台模式也可用。容器有 OpenAI containers API（`/v1/containers`，含文件）；`expires_after`、`memory_limit`、`network_policy` 只能缩小上述设置。详见[服务器端工具](/docs/api/server-tools)。

## 沙箱允许什么

- **写入：** 仅限容器目录。
- **读取：** `/Users`、`/Volumes`、`/home` 与容器根目录一律拒绝；只有该容器本身与 Python 解释器的前缀会被重新允许。你的主目录、密钥、`~/.yunshu` 与其他容器都读不到。
- **网络：** 除非列出，否则没有。loopback 永远无法连接，且允许的名称无法解析到私有网段。
- **其他：** Unix socket、Apple Events 与 `open` 皆关闭。

违规事件只以元数据记录（容器 id、返回码、字节数）；命令、输出与文件内容绝不写入日志。

<Callout type="warn">
允许的域名清单不会检查流量内容。允许像 `github.com` 这样覆盖面广的主机仍可能泄露数据，所以请让清单尽量短。
</Callout>

## 与 Anthropic 容器的差异

- 是 macOS，不是 Linux x86_64。Python 是 Yunshu 所使用的解释器（仅标准库，没有 pandas 或 numpy）。
- 没有 Content Credentials。
- 没有 Content Credentials、容器 skills 与 OpenAI 的 `programmatic_tool_calling`。
- 沙箱在 macOS 的 `sandbox-exec` 下运行，Apple 已将它标为弃用；`srt` 是 0.0.x 版本（已测试：0.0.81）。
