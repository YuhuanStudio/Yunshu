`yunshu` 命令用来启动和管理服务器，也可以作为运行中服务器的客户端。运行 `yunshu --help` 或 `yunshu <command> --help` 可看到实时的帮助文本；本页列出每个命令的功能和可接受的选项。

## 全局选项

全局选项要放在命令名称之前。

| 选项 | 说明 |
|---|---|
| `--url`、`-u` | 与服务器通信的命令所用的服务器 URL。默认 `http://localhost:8000`。也会读取环境变量 `YUNSHU_GATEWAY_URL`。 |
| `--json` | 机器可读的输出。有限执行的命令会在 stdout 打印单个 JSON 结果，进度和表格发送到 stderr。失败时打印 `{"error": "..."}` 并以非零状态码退出。 |
| `--version`、`-V` | 打印版本后退出。 |

```bash
yunshu --json model list
yunshu --url http://localhost:8001 --json complete "Hello"
```

在 `--json` 模式下，用法错误（未知的选项、缺少参数）也会以 JSON 错误对象输出到 stdout。退出码并不统一：2 用于输入和连接错误，1 用于操作失败。`yunshu doctor` 在任何检查失败时以 1 退出。

当 CLI 自己的环境或配置文件中设置了 `YUNSHU_AUTH_TOKEN` 时，调用服务器的命令会发送 `Authorization: Bearer <token>`。

## 命令概览

| 分组 | 命令 |
|---|---|
| 开始使用 | `setup`、`doctor`、`pull`、`serve`、`service`、`chat`、`completion` |
| 服务器与模型 | `model`（别名 `models`）、`config`、`status`、`top`、`launch`、`cache` |
| 评估与诊断 | `statusline`、`eval`、`bench`、`diagnose` |
| 推理（调用运行中的服务器） | `complete`、`embed`、`tokenize`、`detokenize`、`rerank`、`classify`、`score`、`transcribe`、`speak`、`ocr`、`image`、`image-edit`、`image-variations`、`voices`、`cancel` |

## 开始使用

### `yunshu setup`

从本地的完整模型（模型目录和 Hugging Face 缓存）中选一个，或输入要下载的 Hugging Face MLX 仓库，然后打印应该运行的 `yunshu serve` 命令。它不会启动服务器。需要交互式终端；在 `--json` 模式或没有终端时，会以错误退出，并列出找到的模型和下一步。

### `yunshu doctor`

检查这台 Mac 能否运行 Yunshu，并为每个问题打印修复方式。涵盖的项目参见[安装](/docs/getting-started/install)。

| 选项 | 说明 |
|---|---|
| `--model`、`-m` | 一并检查此模型（路径或 repo id）。默认为 `YUNSHU_MODEL` 设置。 |
| `--host` | 你将要服务的主机（用于端口检查）。默认 `127.0.0.1`。 |
| `--port`、`-p` | 你将要服务的端口。默认 `8000`。 |
| `--no-metal` | 跳过导入 MLX 和 GPU 探测。 |

任何检查失败时退出状态为 1。`--json` 返回 `{version, ok, checks}`。

### `yunshu pull REPO_ID`

把 Hugging Face 模型下载到模型目录。也可使用 `yunshu model pull`。

| 选项 | 说明 |
|---|---|
| `--dir`、`-d` | 下载到此目录。 |
| `--revision`、`-r` | 分支、标签或 commit。 |
| `--force` | 即使模型已在磁盘上也下载（只获取缺少或已变更的文件）。 |

参见[模型](/docs/getting-started/models)。

### `yunshu serve [MODEL]`

启动推理服务器。模型可以用位置参数或 `--model` 指定；两者给了不同的值会报错。若既没有配置模型也没有配置模型目录，交互式终端会提示你选择模型；否则命令会失败并提示下一步。若引用匹配模型目录或 Hugging Face 缓存中的模型，会服务该本地副本而不是下载。

| 选项 | 说明 |
|---|---|
| `--model`、`-m` | 模型路径或 Hugging Face id（单模型模式）。 |
| `--models-dir`、`-d` | 要扫描模型的目录（多模型模式）。 |
| `--host`、`-h` | 绑定的主机。默认 `127.0.0.1`。绑定非本机主机又没有 token 时会打印警告。 |
| `--port`、`-p` | 绑定的端口。默认 `8000`。 |
| `--uds` | 改在此 Unix domain socket 上服务而非 TCP；`--host` 和 `--port` 会被忽略。 |
| `--workers`、`-w` | worker 进程数。默认 `1`。 |
| `--max-memory` | 模型可用的 GPU 内存上限，例如 `32GB`，或 `disabled`。 |
| `--completion-batch` | 补全批大小（设置 `YUNSHU_COMPLETION_BATCH_SIZE`）。 |
| `--max-concurrent` | 最大并发请求数（设置 `YUNSHU_MAX_CONCURRENT`）。 |
| `--auth-token` | 请求必须携带的 bearer token（设置 `YUNSHU_AUTH_TOKEN`）。 |
| `--mcp-config` | MCP 配置文件的路径。 |
| `--hf-endpoint` | 自定义的 Hugging Face Hub 端点。 |
| `--http-proxy`、`--https-proxy`、`--no-proxy` | 下载时使用的代理设置。 |
| `--log-level` | `trace`、`debug`、`info`、`warning` 或 `error`。默认 `info`。 |
| `--startup-timeout` | 等待模型加载的最长秒数。 |
| `--slow-request-threshold` | 请求超过此秒数时记录警告。 |
| `--drain-timeout` | 关闭时让进行中请求完成的秒数。 |
| `--keep-alive-timeout` | 空闲连接保持打开的秒数（0 表示禁用）。 |
| `--max-request-size` | 请求体大小上限（字节）。 |
| `--server-header` | 在响应中发送 `Server: Yunshu`。 |
| `--reload` | 开发用的自动重新加载。 |
| `--config`、`-c` | 含 `YUNSHU_*` 设置的 TOML 文件。 |
| `--set KEY=VALUE` | 覆盖任一设置；`YUNSHU_` 前缀可省略，可重复使用。未知的名称会报错并列出最接近的名称。 |

标志和 `--set` 的优先级最高，高于环境变量和配置文件。加载之前，`serve` 会确认地址可以绑定，并运行与 `doctor` 相同的模型检查；无法加载的模型仍会让服务器启动，由 `GET /health/ready` 报告原因。使用 `--json` 时会先打印 `starting` 事件，之后进程持续运行；就绪状态请看 `GET /health/ready`，而不是这个事件。所有设置参见[配置](/docs/guides/configuration)。

### `yunshu service`

通过 launchd 在登录时运行 Yunshu。子命令：`install`、`uninstall`、`start`、`stop`、`restart`、`status`、`logs`、`rotate-logs`。完整选项参见[服务](/docs/getting-started/service)页面。

### `yunshu chat`

与运行中服务器的交互式终端对话。不支持 `--json`。

| 选项 | 说明 |
|---|---|
| `--model`、`-m` | 模型名称。默认为服务器列出的第一个模型，优先选择已知的对话模型系列。 |
| `--url`、`-u` | 服务器 URL。默认 `http://localhost:8000`。 |
| `--system`、`-s` | 系统提示词。 |
| `--temperature`、`-t` | 采样温度。默认 `0.7`。 |
| `--max-tokens` | 最大输出 token 数。默认 `2048`。 |
| `--thinking` | 启用思考模式。 |
| `--no-stream` | 禁用流式输出。 |

对话中可用：`/clear`、`/thinking`、`/model <name>`、`/help`、`/quit`（也可用 `/exit`、`/q`）。

### `yunshu completion SHELL`

打印 `zsh`、`bash` 或 `fish` 的 shell 自动补全脚本。它不会修改你的 shell 文件。

```bash
mkdir -p ~/.zfunc
yunshu completion zsh > ~/.zfunc/_yunshu     # 在 compinit 之前把 ~/.zfunc 加入 fpath
yunshu completion bash > ~/.yunshu-completion.bash
yunshu completion fish > ~/.config/fish/completions/yunshu.fish
```

## 服务器与模型

### `yunshu model`（别名 `models`）

| 子命令 | 用途 |
|---|---|
| `list` | 列出磁盘上的模型，或以 `--url` 列出服务器上的模型。选项：`--dir`/`-d`、`--hf-cache`/`--no-hf-cache`、`--url`/`-u`。 |
| `pull REPO_ID` | 与 `yunshu pull` 相同。 |
| `info MODEL`（别名 `show`） | 显示模型名称或路径的类型、大小、文件数量和 `config.json` 主要字段。 |
| `rm MODEL` | 按完整名称删除已下载的模型。`--yes`/`-y` 跳过确认（配合 `--json` 时必须使用）。 |
| `load MODEL` | 在运行中的服务器加载模型（`POST /v1/models/load`）。 |
| `unload MODEL` | 从运行中的服务器卸载模型（`POST /v1/models/unload/{model_id}`）。 |
| `benchmark MODEL` | 在本地进程内运行生成性能测试（以 mlx-lm 加载模型，因此适用于文本模型；会使用 GPU）。选项：`--prompt-tokens`（128）、`--max-tokens`（256）、`--runs`/`-n`（3）、`--warmup`（1）。 |

`load` 和 `unload` 接受 `--url`/`-u`。

### `yunshu config`

显示每个稳定设置的有效值和来源（`cli`、`env`、`file` 或 `default`），以及警告和网络搜索提供方的健康状态。

| 选项 | 说明 |
|---|---|
| `--all`、`-a` | 包含实验性和内部设置。 |
| `--json` | 打印 JSON。 |
| `--config`、`-c` | 一并读取此 TOML 文件。 |

子命令：

| 子命令 | 用途 |
|---|---|
| `config set KEY VALUE` | 把设置存入 `~/.yunshu/config.toml`（或以 `--config`/`-c` 指定的文件）。键名可省略 `YUNSHU_`；值会经过验证。路径类设置以绝对路径保存。 |
| `config unset KEY` | 从文件中移除设置。 |
| `config path` | 打印用户配置文件的位置。 |

### `yunshu status`

显示服务器健康状态、GPU 和内存使用量、请求计数，以及服务器列出的模型。选项：`--url`/`-u`。无法连接到服务器时会以错误退出。

### `yunshu top`

与 `status` 相同，但以循环持续刷新。选项：`--url`/`-u`、`--once`（打印一次快照后退出）、`--interval`（秒，默认 `2.0`，最小 `0.5`）。配合 `--json` 时返回一次快照。

### `yunshu launch [TOOL]`

为外部的编程工具配置好你的服务器并启动它。`TOOL` 可为 `claude`、`codex`、`opencode`、`pi`，或 `list`（默认），后者显示这些工具及其是否已安装。

| 选项 | 说明 |
|---|---|
| `--model`、`-m` | 要使用的模型。默认为服务器所服务的模型。 |
| `--url`、`-u` | 服务器 URL。 |
| `--api-key`、`-k` | 交给工具的 API 密钥。 |
| `--effort` | Claude Code 的推理强度（`low`、`medium`、`high` 等）。 |
| `--statusline` / `--no-statusline` | Claude Code：在状态栏显示实时引擎状态（默认开启），除非你已有自己的状态栏。 |
| `--dry-run` | 只打印配置，不写入也不启动工具。 |

### `yunshu cache`

查看并清理 SSD 前缀缓存（仅限已启用的缓存）。

| 子命令 | 用途 |
|---|---|
| `status` | 每个缓存的大小、上限和问题。不做任何更改。 |
| `gc` | 找出被截断、损坏和旧格式的条目、孤立的临时文件、过期的命名空间，以及超过容量上限的条目。除非加上 `--apply`，否则只报告。 |

## 评估与诊断

### `yunshu diagnose`

| 子命令 | 用途 |
|---|---|
| `gpu` | GPU 和 Metal 能力的详细信息（在本地使用 MLX）。 |
| `server` | 检查运行中服务器的健康状态和统计。选项：`--url`/`-u`。 |
| `bundle` | 写出本地诊断文件：版本、平台、软件包版本、已屏蔽机密的设置、doctor 检查结果、SSD 缓存状态，以及服务日志中最近的错误行。不含提示词、补全内容和模型权重，也不会上传。选项：`--output`/`-o`（默认 `./yunshu-diagnostics-<time>.json`）、`--host`、`--port`/`-p`。 |

### `yunshu eval BENCHMARK`

对运行中的服务器运行准确度基准测试。`BENCHMARK` 可为 `mmlu`、`gsm8k`、`hellaswag`、`truthfulqa`、`humaneval`、`arc`、`piqa`，`all` 表示全部运行，`list`（默认）则列出可用项目。

| 选项 | 说明 |
|---|---|
| `--url`、`-u` | 服务器 URL。 |
| `--model`、`-m` | 要评估的模型。 |
| `--sample`、`-n` | 采样数量（0 表示使用完整数据集）。 |
| `--quick`、`-q` | 以 50 条样本快速运行。 |

### `yunshu bench`

| 子命令 | 用途 |
|---|---|
| `roofline` | 在本地 GPU 上测量矩阵乘法 roofline。选项：`--min`（64）、`--max`（8192）、`--dtype`（`float16`）、`--steps`（8）。 |
| `memory` | 显示 Apple Silicon 内存布局和 MLX 分配量。 |
| `inference` | 本地进程内的生成性能测试。选项：`--model`/`-m`（路径）、`--prompt-len`、`--max-tokens`、`--requests`/`-n`、`--batch`/`-b`、`--warmup`。 |
| `latency` | 对运行中服务器测量延迟。选项：`--url`/`-u`、`--model`/`-m`、`--prompt`（32 token）、`--max-tokens`（64）、`--requests`/`-n`（10）。 |
| `throughput` | 对运行中服务器测量吞吐量。选项：`--url`/`-u`、`--model`/`-m`、`--concurrency`/`-c`（4）、`--requests`/`-n`（20）、`--max-tokens`（128）。 |

`roofline`、`memory` 和 `inference` 会在本地运行 MLX 并使用 GPU；服务器正忙于实际工作时请勿运行。

### `yunshu statusline`

为编程智能体的状态栏打印单行引擎状态：进行中请求的 prefill 进度、解码速度和前缀缓存命中，数据来自 `GET /v1/yunshu/status`。以管道输入时，会从 stdin 读取 Claude Code 的 session JSON。服务器无法连接时会打印简短标记而不是失败。选项：`--url`/`-u`、`--api-key`/`-k`（或 `YUNSHU_API_KEY`）。

## 推理命令

这些命令向运行中的服务器发送单个请求（`--url`/`-u`，默认 `http://localhost:8000`）。它们是非交互式的，可配合 `--json`。`--model`/`-m` 默认为 `local`，在单模型模式下可被接受。

| 命令 | 请求 | 备注 |
|---|---|---|
| `complete PROMPT` | `POST /v1/chat/completions` | 选项：`--max-tokens`（256）、`--temperature`/`-t`（0.7）、`--system`/`-s`。 |
| `embed TEXT` | `POST /v1/embeddings` | 打印维度和前几个值；`--json` 返回完整向量。 |
| `tokenize TEXT` | `POST /v1/tokenize` | 打印 token 数；`--ids` 返回 token id。 |
| `detokenize TOKEN...` | `POST /v1/detokenize` | 把 token id 转回文本。 |
| `rerank QUERY DOC...` | `POST /v1/rerank` | `--top-n` 限制结果数量（0 表示全部）。 |
| `classify TEXT LABEL...` | `POST /v1/classify` | 针对给定标签的零样本分类。 |
| `score TEXT1 TEXT2` | `POST /v1/score` | `--type` 为 `cosine`（默认）、`dot` 或 `euclidean`。 |
| `transcribe FILE` | `POST /v1/audio/transcriptions` | `--language`/`-l`；`--translate` 改用 `POST /v1/audio/translations`。 |
| `speak TEXT` | `POST /v1/audio/speech` | 必须指定 `--out`/`-o`（.wav 或 .mp3）；`--voice`（默认 `ethan`）。 |
| `voices` | `GET /v1/audio/voices` | 列出 `speak` 可用的声音。 |
| `ocr FILE` | `POST /v1/ocr` | 从图片文件提取文本。 |
| `image PROMPT` | `POST /v1/images/generations` | 必须指定 `--out`/`-o`；`--model`/`-m`（默认 `Z-Image-Turbo-MLX-4bit`）、`--size`（`1024x1024`）、`--steps`（4）。 |
| `image-edit FILE PROMPT` | `POST /v1/images/edits` | 必须指定 `--out`/`-o`；`--model`/`-m`、`--steps`、`--strength`（0.8）。 |
| `image-variations FILE` | `POST /v1/images/variations` | 必须指定 `--out`/`-o`；`--model`/`-m`、`--steps`。 |
| `cancel [REQUEST_ID]` | `POST /v1/cancel` | 取消单个生成，或以 `--all` 取消全部。 |

```bash
yunshu complete "Explain unified memory in one sentence." --max-tokens 80
yunshu tokenize "hello world" --ids
yunshu rerank "apple pie recipe" "How to bake a pie" "Stock prices today"
yunshu speak "Hello from Yunshu" --out hello.wav
```

请求能否成功取决于已加载的模型和已安装的额外依赖；参见[模型支持](/docs/guides/model-support)。
