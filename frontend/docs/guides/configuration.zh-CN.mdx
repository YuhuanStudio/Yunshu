title: 配置
description: 所有 YUNSHU_* 设置的类型与默认值，由设置注册表生成。
---

每个 Yunshu 设置都是注册在 `python/yunshu_engine/settings.py` 的 `YUNSHU_*` 名称，各有唯一的类型、默认值与解析规则。
除此之外没有任何代码会读取 `YUNSHU_*` 环境变量。

## 设置值的来源

优先级由高到低：

1. `yunshu serve` 的参数与 `--set KEY=VALUE`（可重复；`KEY` 可省略 `YUNSHU_` 前缀，例如 `--set mtp_block_size=4`），
2. 进程的环境变量，
3. TOML 配置文件：`yunshu serve --config yunshu.toml` 或 `YUNSHU_CONFIG=yunshu.toml`，
4. 下表列出的默认值。

配置文件是一组 `KEY = value`，可以平铺，也可以放在任意表（table）之下（表名会被忽略，键可用短名或全名）：

```toml
model = "~/models/Qwen3.8-27B-4bit"

[server]
default_max_tokens = 1024

[voice]
YUNSHU_REALTIME_SILENCE_MS = 400
```

布尔值接受 `1/true/yes/on` 与 `0/false/no/off`。无法解析的值会在启动时作为错误，并列出所有有问题的设置。
未注册的 `YUNSHU_*` 名称会被忽略，并以警告指出最接近的已注册设置。

`yunshu config` 会打印每个稳定设置的有效值与来源（`cli`、`env`、`file`、`default`）；`--all` 会加上实验性与内部设置，
`--json` 输出 JSON，`--config FILE` 会纳入配置文件。

## 稳定性

- **stable**：受支持的部署设置。
- **experimental**：临时性。每一项都注明由哪一项测量决定去留与加入时间；测量完成后，胜出者成为默认，标志与落败的代码路径会被删除。同一时间最多 8 项。
- **internal**：调试辅助。

下表的说明直接来自设置注册表，所有语言都以英文呈现。

## 稳定设置

### model

| Setting | Type | Default | Applies | Description |
|---|---|---|---|---|
| `YUNSHU_MODEL` | path | unset | restart | Model path or Hugging Face id served in single-model mode; every requested model name maps to it. |

| `YUNSHU_MODELS_DIR` | path | unset | restart | Directory of model folders for multi-model mode (each folder name is a model id). Unset: ~/.yunshu/models (also where `yunshu pull` downloads to). |
| `YUNSHU_HF_CACHE_MODELS` | bool | on | live | Multi-model mode: also offer models already in the Hugging Face cache (the models directory wins on name clashes). `yunshu serve -m org/name` uses a cached copy either way. |
| `YUNSHU_MODEL_TTL_SECONDS` | float | unset | restart | Multi-model mode: unload a model idle for this many seconds. Unset: never. |
| `YUNSHU_ALLOW_AUTO_LOAD` | bool | off | live | Multi-model mode: let audio requests load a model that is not loaded yet (otherwise they are rejected). |
| `YUNSHU_MAX_LORAS` | int | 4 | reload | Maximum LoRA adapters kept loaded (text models). |
| `YUNSHU_TRUST_REMOTE_CODE` | bool | off | reload | Allow Hugging Face tokenizers/processors that need trust_remote_code. |
| `YUNSHU_WARM_PROMPTS` | str | unset | reload | Prompts prefilled at startup to warm the prefix cache: '\|\|'-separated text or file paths. |

### server

| Setting | Type | Default | Applies | Description |
|---|---|---|---|---|
| `YUNSHU_CONFIG` | path | unset | restart | TOML config file with YUNSHU_* settings (lower precedence than the environment). |
| `YUNSHU_MAX_CONCURRENT` | int | unset | restart | Cap on concurrently admitted requests. Unset: adaptive (starts at 8). |
| `YUNSHU_UNCACHED_SCHEDULING` | bool | on | reload | Order VLM canonical prefill atoms by estimated uncached RAM-prefix work and wait time, protect interactive prefills after one overtaking atom, age waiters after 10 seconds, and reserve up to 75 ms of measured decode time between prefill atoms; finish an interactive request's last 2048-token window and deliver its first token before repaying decode debt. No token spans change; SSD-only hits are conservatively estimated cold. Defaults on only with engaged qualified batch-invariant kernels; other backends keep FIFO unless explicitly enabled. Disable to restore upstream ordering. |
| `YUNSHU_DECODE_TAIL_SHARE` | float | 0.5 | reload | Share of GPU time running decode rows are owed after each prefill atom of a newcomer, once every running row is past its first 48 tokens: a prefill atom of t seconds earns decode time share*t (0.075-4 s). The same GPU time is divided either way. Measured on the 27B with one long reply running and a cold 4K / 32K prompt arriving (3 interleaved reps): 0.25 gave the running row 5.0 tok/s and the newcomer first token after 7.0 s / 58 s; 0.5 gave 7.6 tok/s at 7.8 s / 68 s; 1.0 gave 11.2 tok/s at 9.8 s (4K). | `YUNSHU_AUXILIARY_SCHEDULING` | bool | on | reload | Deprioritize captured opencode title requests: interactive VLM jobs run first; auxiliary rows pause between GPU slices and never read or write APC. In-flight GPU operations cannot be interrupted. |
| `YUNSHU_QUEUE_LIMIT` | int | 64 | live | Generation requests (chat, completions, messages, responses) in flight at once, running and waiting together. The next one is refused at once with 429, `Retry-After` and the queue depth in `error.x_yunshu` instead of waiting without bound. 0 = no limit. |
| `YUNSHU_MEMORY_PRESSURE_REJECT` | float | 0.95 | live | Share of the Metal working set (MLX active memory / recommended working set) above which, while other requests are running, a new generation request is refused with 503 and `Retry-After` (it would OOM the process). | `YUNSHU_ORPHAN_GRACE_SECONDS` | float | 120.0 | live | Orphan adoption: when a client disconnects mid-generation (an agent timing out a long streamed reply), keep that generation running for this many seconds instead of cancelling it. Two live identical requests are never merged. A cancel request or deadline still stops at once; unadopted generations are cancelled when the window ends. Observed: Claude Code re-sends 5 s to 14 min after cutting a stream. 0 = cancel at disconnect. |
| `YUNSHU_ORPHAN_MAX` | int | 2 | live | Most orphaned generations kept at once (each still holds its decode row and KV until adopted or expired; the oldest is cancelled beyond this). |
| `YUNSHU_COMPLETION_BATCH_SIZE` | int | 32 | restart | Text engine: maximum sequences decoded together. |
| `YUNSHU_SAMPLING_DEFAULTS` | `model` \| `api` | model | reload | Where a request that omits a sampling parameter gets it: 'model' (the model's published per-mode recommendation, then its generation_config.json, then the API default) or 'api' (the official API default only: temperature 1.0, top_p 1.0, others off). A value in the request always wins. |
| `YUNSHU_DEFAULT_MAX_TOKENS` | int | 0 | reload | Operator cap on the output length of a chat / responses request that omits max_tokens / max_output_tokens. 0 (default) = the model's output limit (262144, Qwen3.8 card: thinking mode), which the API specs define as the default; the context window still clamps it (x_yunshu.budget reports the effective value and its source). A positive value lowers the default only; an explicit request value is never capped by it. |
| `YUNSHU_MAX_PREFILL_TOKENS` | int | 0 | live | Reject prompts longer than this many tokens (0: no limit beyond the model context). |
| `YUNSHU_STARTUP_TIMEOUT` | float | 300.0 | restart | Seconds to wait for the model to load before startup fails. |
| `YUNSHU_DRAIN_TIMEOUT` | float | 30.0 | restart | Seconds to wait for in-flight requests on shutdown. |
| `YUNSHU_KEEP_ALIVE_TIMEOUT` | int | 5 | restart | Seconds an idle HTTP connection stays open. |
| `YUNSHU_UDS` | path | unset | restart | Serve on this Unix domain socket instead of a TCP port (same app; curl --unix-socket, httpx uds=). |
| `YUNSHU_WS_MAX_INFLIGHT` | int | 16 | live | Text WebSocket (/v1/stream, wss /v1/responses): maximum concurrent requests per connection. |
| `YUNSHU_WS_PING_INTERVAL` | float | 15.0 | live | Text WebSocket: seconds between server heartbeat pings (0 disables). |
| `YUNSHU_WS_SEND_QUEUE` | int | 256 | live | Text WebSocket: outbound events buffered per connection before generation is paused (backpressure). |
| `YUNSHU_MAX_REQUEST_SIZE` | int | 33554432 (32 MiB) | restart | Maximum request body size in bytes. | `YUNSHU_PROGRESS_INTERVAL_S` | float | 2.0 | live | Streaming chat/completions: seconds between `: yunshu-progress` SSE comments (queue / prefill progress, ETA) before the first token; 0 turns them off. Strict SSE clients ignore comment lines. |
| `YUNSHU_SLOW_REQUEST_THRESHOLD` | float | 30.0 | restart | Log a warning for requests slower than this many seconds. |
| `YUNSHU_CORS_ORIGINS` | str | http://localhost:3000,http://localhost:8000 | live | Comma-separated allowed CORS origins ('*' for any). Also checked for the Realtime WebSocket Origin header. |
| `YUNSHU_RESPONSE_CACHE` | bool | off | restart | Cache identical non-streaming responses in memory. |
| `YUNSHU_BATCH_MAX_ITEMS` | int | 100000 | live | Batch API: maximum requests per batch (also capped by the protocol limits: 50,000 OpenAI, 100,000 Anthropic). |

| `YUNSHU_ALLOW_LOCAL_FILES` | bool | off | live | Allow requests to reference any local file path (default: only under YUNSHU_MEDIA_DIR). |

| `YUNSHU_FILES_MAX_BYTES` | int | 536870912 (512 MiB) | live | Files API: maximum size of one uploaded file in bytes (default 512 MB). |
| `YUNSHU_FILES_TTL_DAYS` | float | unset | live | Files API: delete uploaded files after this many days. Unset: keep forever. |

| `YUNSHU_COMPACT_MAX_TOKENS` | int | 2048 | live | Responses compaction: maximum tokens of the model-written summary. |

### vlm-runner

| Setting | Type | Default | Applies | Description |
|---|---|---|---|---|
| `YUNSHU_VLM_APC_DRAFT_WINDOW_GB` | float | 0.25 | restart | RAM budget in GiB for the DFlash drafter context windows kept beside APC checkpoints (about 0.1 GiB each at 2047 positions). On a prefix hit the drafter starts with the stored window instead of only the uncached suffix, which restores its acceptance (lossless: the target verifies every draft). 0 disables. |
| `YUNSHU_VLM_APC_MEMORY_GB` | float | unset | reload | VLM runner prefix cache (APC) RAM budget in GiB; 0 disables the prefix cache. Unset: half of the memory left after the model weights and an OS / activation reserve (a quarter of the machine, 4 to 16 GiB), at most a quarter of the machine and 32 GiB, and 0 (off) when under 1 GiB would be left (128 GB machine, 27B model: 32; 8 GB machine, 4B model: 0). A 27B checkpoint costs about 130 KiB per cached token. |
| `YUNSHU_VLM_APC_DISK` | bool | on | reload | APC SSD tier: prefix checkpoints that RAM evicts (and, at shutdown, those still resident) are written to disk and read back instead of re-prefilling (bit-exact states, lossless; a 27B checkpoint reloads about 20x faster than it prefills). Set 0 to keep the prefix cache in RAM only. |
| `YUNSHU_VLM_APC_DISK_DIR` | path | unset | reload | Directory of the APC SSD tier. Unset: ~/.yunshu/cache/apc (internal disk). Put it on a fast volume to keep the internal disk clean. |
| `YUNSHU_KV_PRECISION` | `bf16` \| `int8` | bf16 | reload | KV cache precision of the Qwen3.5-family runner's shared decode batch: 'bf16' (lossless) or 'int8' (int8 codes + one fp16 scale per 32-dim group: ~0.53x the KV memory and read bandwidth for a small attention error; memory vs quality). A lone request and the speculative lane stay bf16; a request that joins a shared batch has its KV converted to int8 at the join, so with int8 a reply can depend on whether other requests overlapped it. Applies to models with Qwen3.5-family attention (the ragged KV layout). |
| `YUNSHU_VLM_APC_DISK_GB` | float | unset | reload | Size cap of the APC SSD tier in GiB, one budget for the whole directory (every checkpoint namespace together; least recently used files go first across namespaces; 0 = no configured cap, the free-space reserve still applies). Unset: a quarter of the volume, at most 64 GiB (a 128 GB disk: 32). A 27B checkpoint costs about 130 KiB per token, so 64 GiB holds about 500K tokens. |
| `YUNSHU_PREFILL_MATMUL` | `stock` \| `lane` | stock | reload | Qwen3.5-family VLM prefill matmul. On the qualified Qwen3.8-27B / M5 Max / MLX 0.32.3 path, stock selects native NAX for every prompt piece (short pieces pad input rows to 64 and crop output); narrow gates and the vocabulary head keep their row-invariant lane arithmetic. Decode and speculative verify keep their existing kernels. Other configurations retain the legacy stock dispatch above 512 rows. lane keeps lane matmul throughout. Prefill arithmetic is isolated by APC kernel_id and SSD namespace. |
| `YUNSHU_PREFILL_BUFFER_CACHE_GB` | float | unset | reload | VLM runner: GiB of MLX's freed-buffer cache kept across prefill steps. Unset: 5% of physical RAM, at most 6 GiB (128 GiB: 6; 8 GiB: 0.4), but 0.5 GiB when the resident weights leave little headroom (above 80% of YUNSHU_MAX_MEMORY_GB when set, else above 45% of RAM): lossless, it cuts the long-prefill peak of a 74 GB model by 5-10 GB. Uses MLX's cache limit to reclaim excess freed memory on the next allocation without clearing every reusable bucket; freed buffers may transiently exceed the limit until that allocation. Keeps long-prefix restore buffers warm across requests. 0 = upstream clear after every chunk. Allocator only; output unchanged. |
| `YUNSHU_PREFILL_GDN` | `chunked` \| `step` | chunked | reload | Qwen3.5-family VLM prefill recurrence. chunked uses mx.fast.gated_delta_update; the qualified split-invariant 27B path uses it for every prompt piece, padding short tails to 64 with identity updates that preserve fp32 state. Checkpoints and resumable cuts are absolute 64-token boundaries. step retains the per-token kernel and disables split-invariant mode. Decode and speculative verify retain their existing kernels. Part of the APC arithmetic namespace. |
| `YUNSHU_PREFILL_ATTENTION` | `tile` \| `stock` | tile | reload | Qwen3.5-family VLM prefill attention on the qualified M5 Max / MLX 0.32.3 pair (bf16, D=256, causal, plain KV). tile uses BQ32 NAX attention; the qualified split-invariant 27B path uses it for every query length, including unaligned short tails. Other configurations retain the 1024-row threshold. stock disables split-invariant mode. Decode and speculative verify retain their kernels. Split-invariant attention is included in the APC arithmetic namespace. |
| `YUNSHU_ANE_FFN_SPLIT` | `off` \| `splash` | off | restart | Qwen3.5-family VLM prefill (single-row prompt steps of at least the calibrated rows): `splash` splits each dense FFN layer by intermediate channel between the GPU and the Apple Neural Engine, as Splash does (Apache-2.0 port): the ANE runs a W8A8 share (int8 weights rotated by a block Hadamard transform, int8 activations) through the private AppleNeuralEngine API on IOSurface memory shared with Metal, ordered by a shared event inside the GPU command stream. LOSSY: the ANE's part differs from the GPU's by about 2.5% RMS of what it adds, so outputs and logprobs differ slightly from `off`; prefix-cache states are kept apart by the kernel id. The share and the least chunk come from a calibration on this Mac (about a minute at first start, remembered per model and device). Any ANE failure or a split that loses to the GPU alone stops it for the life of the process and the GPU reruns the step. Costs about 0.7 GiB of extra resident memory (ANE surfaces and GPU slice scales). Off by default. |
| `YUNSHU_ANE_FFN_SHARE` | float | unset | restart | With YUNSHU_ANE_FFN_SPLIT=splash: fixed fraction (0-1) of intermediate channels the ANE takes, skipping calibration (rounded to 512-channel units). Unset: calibrated. |
| `YUNSHU_ANE_FFN_TRACE` | bool | off | restart | With YUNSHU_ANE_FFN_SPLIT=splash: log, for each split prompt step, the Neural Engine's milliseconds per layer and the GPU-side gap between layers (diagnostics). |
| `YUNSHU_ANE_FFN_CACHE` | path | unset | restart | With YUNSHU_ANE_FFN_SPLIT=splash: directory of the compiled Neural Engine programs' sources and the remembered calibration. Unset: ~/.yunshu/ane_cache/ffn. |
| `YUNSHU_ANE_FFN_MIN_ROWS` | int | unset | restart | With YUNSHU_ANE_FFN_SHARE: least prompt-step rows that take the split (512-2048, steps of 128). Unset: 512. |
| `YUNSHU_VLM_APC_DISK_TIERS` | str | unset | reload | Further APC storage tiers below the SSD directory, comma-separated, each 'PATH[@GiB]' (an external SSD, an HDD, a NAS mount). Each volume is profiled at startup (sequential read / write bandwidth and latency, cached per mount for a day) and the tiers are ordered by measured read speed. Checkpoints the SSD tier evicts move down in the background instead of being deleted; a tier is used for a hit only when restoring from it beats re-prefilling (measured bandwidth against the observed prefill speed). A tier that is not mounted is skipped; when it returns its files are validated again. Each tier has its own cap (default: a quarter of its volume, at most 64 GiB) and free-space reserve. Lossless; unset: SSD only. |
| `YUNSHU_VLM_APC_DISK_ENCODING` | `auto` \| `raw` \| `zstd` | auto | reload | How the lower APC storage tiers (YUNSHU_VLM_APC_DISK_TIERS) hold a checkpoint: 'raw' (a copy of the SSD file), 'zstd' (lossless: byte-plane shuffle of bf16 tensors + zstd; decoded on restore), 'auto' (zstd only when the measured gain in effective read bandwidth, ratio against decode cost, beats raw on that device: slow disks and network shares, not fast SSDs). | `YUNSHU_VLM_APC_WARM` | `off` \| `lossless` \| `int8` \| `int4` | off | reload | APC WARM tier: what happens to a prefix checkpoint that leaves the RAM tier (HOT, ready-to-use arrays) before it goes to SSD. 'int8' / 'int4': attention K/V kept in RAM as affine group-quantized codes (LOSSY: a hit restores dequantized K/V, so output can differ from a cold prefill; the SSD tier keeps exact states in these modes). The WARM tier takes YUNSHU_VLM_APC_WARM_SHARE of the APC RAM budget. |
| `YUNSHU_VLM_APC_WARM_SHARE` | float | 0.4 | reload | Share of the APC RAM budget (YUNSHU_VLM_APC_MEMORY_GB) that the WARM tier takes when YUNSHU_VLM_APC_WARM is on; the HOT tier keeps the rest. One budget, split: total APC RAM does not grow. |
| `YUNSHU_VLM_MAX_IMAGE_BYTES` | int | 26214400 (25 MiB) | live | Largest image a request may reference by URL, in bytes. |
