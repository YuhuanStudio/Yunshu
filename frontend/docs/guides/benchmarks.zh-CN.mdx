## 如何阅读这些数字

- 每个数值是 2 或 3 次重复的中位数。许多云枢单元格另外进行了一次未计划的第三次重复。
- 研究有两种口径。STRICT 只有在双方都通过每项审计检查时才计入一行，因此只剩 18 个可比行，全部来自批次 B1。REF 还忽略两项记账性失败：B2 中混用了两个 harness 提交，以及一个未计划的额外重复文件。下列每个数字都是 REF 数字。在 REF 下，每个数字所用的云枢一侧只带有 REF 豁免的检查，重启行除外（见其他单元格）。
- 已排除：所有 Kapitsa 单元格（启动的二进制哈希与固定的不一致，因此不使用其 RAW 胜出结果）；tool-chat 解码 tok/s（27 token 的回复使计时窗口过短；tool-chat TTFT 保留）；128K 混合负载的逐行中位数（角色不同；采用汇总值）；重启解码 tok/s（不同引擎之间不可比）；LM Studio（从未运行）。
- 百分比遵循研究口径。正值表示云枢更好。百分比取云枢 main 与云枢 pb2 中较好的一个，而显示的云枢数值为 main 列（与 README 中数值相同）。当 pb2 更快时，显示的比值可能与百分比不同。
- 范围：32K、64K 与 128K 的代码和散文提示词，以及下文列出的并发、混合与重启单元格。该研究不能确立一般质量或一般排名。

## 云枢的定位

在完整矩阵中，REF 共有 114 个可比行。云枢赢 17 行，输 97 行：输给 Splash（37）、TensorFold 1.1.8（36）、TensorFold 1.2.1（22）、llama.cpp（1）与 mlx-serve（1）。其中四十个失败出现在 32K 及以上。

在代码提示词上，TensorFold 在每个深度都领先 27B 解码；在散文上，TensorFold 在 32K 与 64K 领先，Splash 在 128K 散文解码领先。冷 TTFT 在 32K 与 64K 落后于 Splash，在 128K 领先。温 TTFT 在 32K 领先，在 64K 与 128K 落后。后续轮（turn-2）TTFT 在每个深度都落败，其中最大差距出现在 64K（代码 -61.5%）。

### 其他单元格

- 不同的 8K 提示词，聚合解码 tok/s，代码。云枢 main（pb2）在 2、4 与 8 个并发请求下：
  27.3（36.8）、33.0（38.5）与 37.1（39.1）。最佳竞争对手（REF）：TensorFold 1.2.1 42.3、TensorFold 1.2.1 45.1、
  TensorFold 1.1.8 45.2。云枢相对最佳：-13.1%、-14.7% 与 -13.5%。Kapitsa 已排除。
- 混合 128K，代码，8 个并发（一个 128K 长请求和 7 个短请求）。聚合 tok/s：16.1（pb2 18.1），对比 Splash 17.7，+2.0%。长请求 TTFT：222.256 s（pb2 212.084 s），对比 Splash 224.558 s，+5.9%。逐行中位数不是同口径比较，因此不予报告。
- 近似相同缓存下的 turn-2（研究中的 idle5 单元格，代码，32K）：TTFT 0.983 s，已缓存 32704 个 token；对比 TensorFold 1.1.8 的 0.070 s，已缓存 33283 个 token，-92.9%。64K 与 128K 的 turn-2 在代码和散文上落后 31% 至 61%。
- 代码 turn-2 解码，32K：342.2 tok/s（pb2 347.0），对比 Splash 127.2，+168.9%。研究未解释这一结果，因此不将其视为普遍结论。
- 重启，代码，32K：重启 TTFT 32.868 s，对比 mlx-serve 26.11.1 的 0.313 s，-99.0%。两个云枢引擎在重启后都显示 0 个已缓存 token（审计项 `cold_cache` 失败），因此磁盘层恢复未被证明。该重启项已重新开启。
- 结构化输出（json-schema，8K，冷解码）：74.3 tok/s（pb2 24.0，未通过 engaged 模式），对比 TensorFold 1.1.8 的 163.8，-54.6%。
- Flash-Next（Qwen4）不在本次对比之中。

### 研究遗留的待办事项

- Kapitsa 必须重新固定版本（其二进制哈希已变化），其单元格才能计入。
- 有 50 个单元格带有未计划的 r2 文件，需要做出决定，然后重新审计。
- 为整个批次固定同一个 harness 提交（B2 混用了两个）。
- 重新运行 B1 中 pb2 在 32K 与 64K turn-2 的轮次时间异常值。
- 运行 LM Studio，或将其从清单中移除。
- 在真实解码窗口上测量 tool-chat 解码（27 token 的回复使当前 tok/s 失去意义）。
